# 案例带读方式

更新：2026-11-06。

**我们一次研究一个 case，由助手准备材料、讲清链路，再通过讨论逐步深入。**
不是让学习者独立读完所有论文，也不是把候选清单变成复现任务。

已完成本轮阅读：[TinyStories](2026-10-tinystories/README.md)、[AnaDroid](2026-11-anadroid/README.md)、
[When Scaling Meets LLM Finetuning](2026-11-finetuning-scaling/README.md)。后者对应
[第二阶段阅读清单](NEXT_CASES_2026-11.md)第一篇。
当前讨论位置与下一步只在案例 README 中维护。

**每次只讨论一个部分，确认后再写这一部分。文档的顺序与实际讨论一致，不提前写后续
章节，也不预填完整总览；讨论尚未确认的内容，不标记为已完成。**

资料下载、文件校验和入口检查等可独立的机械工作，优先交给 6.1-sol 子代理；
主助手核查结果并负责研究判断、路线选择与讲解。子代理不可用时如实说明并继续处理。

## 1. 研究目标

通过具体案例，理解目标能力怎样落实为数据、模型和训练选择，以及实验能支持什么结论。
长期关注三个问题：

1. 怎样组织数据，让模型学会目标行为？
2. 模型容量、有效数据和计算预算怎样匹配？
3. 怎样增强专项能力，并检查原有能力的变化？

这些问题贯穿讨论，不要求每个案例都能完整回答。

2026-11-02 明确近期用途：以贴近测试业务的案例，学习如何从研究目标设计完整的数据、
模型、训练、评测与业务验证链路，为测试团队积累决策与工程经验。既理解作者怎样做，
也逐步辨明团队迁移时需要什么条件，不预设照搬配方或必须使用某一种训练方法。

## 2. 带读过程

### 2.1 全貌

**助手准备**：核对论文和官方材料，先讲实验目的与目标能力。后续再逐步连接模型起点、
数据、训练和评测，不在第一次讨论中一次展开。

**共同讨论**：先确认整个项目在做什么。学习者可以随时提问，不要求提前通读论文，
也不从一张超参数表开始。

**记录内容**：只把当前讲清的部分写入总览。整体链路随讨论逐步形成，不提前写完。

### 2.2 关键选择

**助手准备**：沿着总览，一次选择一个具体问题，提供一条真实样本、一段必要代码，
或一组实验作为依据。例如：为什么选这种数据，为什么采用这个规模或训练阶段？

**共同讨论**：把输入、处理、监督和预期行为串起来。不懂的基础概念按需补充，不自动
增加一整套课程或手写作业。

**记录内容**：该问题的解释、证据和讨论中重要的理解，按主题整理到案例文档。

### 2.3 实验判断

**助手准备**：选一项关键对照，解释固定了什么、改变了什么、增加了多少数据或计算，
以及怎样评测。

**共同讨论**：结果是否支持作者的解释？有没有其他原因？哪些选择只是做法，还不能
证明是提升的原因？未公开的信息明确标记，不替作者补出实验。

**记录内容**：实验条件、观察结果、可支持的结论与尚存疑问。

### 2.4 案例归纳

**共同讨论**：回到最初的问题，总结哪些认识可以保留、哪些只在特定条件下成立，
以及还想弄清什么。

**助手整理**：将讨论沉淀为连贯文档，合并重复内容，纳入必要 QA；学习者核对并纠正。
不另要求学习者先交一份报告才继续。

当能解释整体链路、辨别关键证据并说清局限时，即可进入下一案例。不要求读完全部
附录、记住全部配置，也不要求每篇都产出自己的训练实验。

## 4. 文档归档

**一个正式开始研究的 case 对应一个独立目录。** 仅处于候选状态的项目保留在目录索引中，
不提前创建空文件夹和整套模板。

每个案例从 README 开始，说明研究目的、当前讨论位置、下一步和官方资料。
总览从实验目的开始，讨论到哪里写到哪里；深入某个问题时再增加主题文档。
具体目录约定见[前沿案例入口](README.md)。

文档记录我们已经讲清的内容、真实证据和仍未解决的问题，不把未讨论的提纲写成已掌握
的结论。跨案例比较使用链接，不复制多份相同内容。
