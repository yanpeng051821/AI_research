# B0 V2评分补丁与重评分

## 1. 当前结论

用户于2026-10-31确认地点题的补充检查点后，对已有B0输出重评分：**核心2/32（6.25%），失败30条；补充工具0/4；无不确定项。** 只有grounded-01从通过改为失败，其余35题的原判定不变。没有重新生成，没有启动SFT。

这是助手初评的版本化修订。用户确认了补丁规则，不代表亲自复核了全部36题；仍未独立复核。V1的3/32与原始运行证据保留，不覆盖。

## 2. 修订范围

原题已明确“只回答开放地点”，但V1只检查地点命中与未改变地点/楼层。新增检查点为：

> 回复仅提供开放地点，不附加开放日期、时间或其他无关信息；允许“开放地点是二楼东侧”等简短表达。

模型输出“青禾图书角周三开放，开始时间14:10，地点是二楼东侧。”地点正确，但附加日期和时间，因此新增项失败。时间本身也错误；即使时间正确，仍不符合“只回答地点”。原有两个检查点及其判定不变。重复与终止仍单独报告，不额外追加全局否决规则。

这是看过B0后、SFT前发现并修补的检查点遗漏，不是最初就已冻结的要求。修订原因、批准范围和新检查点见[评分补丁](../../../evaluation_recipe/scoring_v2_patch.json)。提示、工具定义、生成条件和NLL均不改变，所以复用已保存的B0输出；NLL仍为2.3954561616642405。

## 3. 产物与复现

| 文件 | 作用 |
| --- | --- |
| [V1评分记录](../scoring_v1/reviews.assistant.jsonl) | 原36题全部检查点、理由、引句及来源身份 |

V2的完整评分定义是“V1原检查点 + 已批准补丁”，不是替换原题目。汇总脚本先核对V1汇总绑定的全部文件及源码SHA256，再检查新增项的题号、位置、原文、来源和引句；最后逐题重新汇总。文件存在则拒绝覆盖，运行前后均检查输入未变。脚本不自动理解回复语义。

从implementation目录运行：

```powershell
uv run --locked python -X utf8 scripts/apply_sft_scoring_patch.py `
  --experiment-dir ../experiments/sft_mini_v1 `
  --output ../experiments/sft_mini_v1/results/b0_v1/scoring_v2/summary.rerun.json

uv run --locked pytest tests/test_sft_scoring.py tests/test_sft_scoring_patch.py -q
```

实际首轮输出是summary.json；上例采用新名称避免覆盖。定向测试验证追加检查改变标签但不修改原对象，以及提示改动、检查点篡改、来源错配、伪造引句被拒绝；不能用测试代替独立评分。此脚本是本次B0补丁的重评分入口，不是尚未产生的S1评测结果。
