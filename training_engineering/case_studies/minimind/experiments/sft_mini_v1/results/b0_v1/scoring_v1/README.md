## 2. 评分方法与证据

[reviews.assistant.jsonl](reviews.assistant.jsonl)保存每题、每个冻结检查点的 pass/fail/uncertain、判定理由与原文引句，绑定题目/输出整文件及逐行SHA256。不修改既有题目、检查点、生成结果、停止方式或运行合同。

任一检查点失败则整题失败；全部通过才通过；没有失败而仍有不确定时为不确定。消极约束必须按自己的范围判断：“没有编造平均年龄”可以通过，但没有说明信息不足仍会让该题失败，不能把无内容回答当成成功澄清。

重复和长度上限按原合同单独记录，不作为事后新增的一票否决。评分看语义关系，不仅查关键词；引用证据仅取原始输出中真实存在的片段，没有运行输出中的代码或工具。

[aggregate_sft_scores.py](../../../../../implementation/scripts/aggregate_sft_scores.py)只做来源/覆盖/检查点/引句和汇总一致性验证，不自动判断理由是否正确。[summary.json](summary.json)给出的上下界只处理判分不确定项，不是统计置信区间。当前不确定为0，因此两界相同。该脚本及两个定向测试没有替代独立语义复核。

## 3. 典型判定与评分缺口

### 3.1 内容命中与质量问题分开

- **grounded-04：通过。** 输出“小叶想带饼干，不接收任何食品”，足以回答饼干不在接受范围，且未放宽规则。但整段反复重复，终止和表达质量仍有明显问题。
- **grounded-07：通过。** 输出“小许把钥匙放在书架顶部”，与书架顶层语义一致，未误用最初的绿色盒子；重复现象没有被原规则设为此题内容判分条件。

这些通过不能解释为我们已经得到了两条可直接交付的好回复；它们只是内容检查和输出质量分开的具体例子。

### 3.2 地点题的检查点漏项

**grounded-01 按V1检查点通过，但完整回答有问题。** 原题只要求地点，材料开始时间为14:20。输出反复说“青禾图书角周三开放，开始时间14:10，地点是二楼东侧”。

冻结检查点只有“答案包含二楼东侧”和“不添加记录之外的具体地点或改变楼层”。它满足这两项，却添加并改错了时间，也违反只回答地点的要求。因此本次保留V1通过标签，同时记录两个质量观察/评分漏项；不能为了得到更合理的分数，悄悄把未冻结的要求补进评分。

这暴露的是检查点覆盖不完整，不是错误时间变成正确。若下一步确认需要修补，应在任何SFT/S1之前创建明确的V2评分版本，并对B0和S1一致使用。若只改评分而提示/生成条件未变，可对已保存的原始生成做版本化重评分，不必重算模型；若输入或生成条件改变，则重新建立受影响的生成基线。V1记录保留，不覆盖。

### 3.3 关键词命中不等于任务完成

**context-03：失败。** 用户问排除了哪种颜色，输出“我在红色文件夹中选择了红色文件夹”。虽然包含红色，却将排除关系变成选择关系，不能只用关键词命中判通过。

**context-05：失败。** 输出仅空白，没有编造代码或执行结果，但也没有指出缺代码并请求提供。第二项消极约束通过，不足以补偿第一项任务缺失。

**instruction-01：失败。** 反复生成“我是你的”，完整输出不能解析为要求的JSON对象；不能只评价语言流畅或是否正常退出。

## 5. 结论与下一步

在本轮固定对话模板、预填空think和贪心条件下，B0未满足大部分任务检查；已保存的输出显示重复、偏题、格式不遵守和上下文关系使用不足。不能将本批低分扩展成对模型全部续写能力的否定，也不能仅凭这些现象确定唯一原因，或保证SFT一定修好。

下一步先共同查看上述几个典型判分，确认是否需要只修补已明确暴露的评分漏项，再在训练前确定改善幅度、允许回退、结束/重复行为目标及训练预算。不扩大为一轮无边界的新出题或数据清洗，也不在此自动冻结训练配方。

## 6. 汇总命令与工程核对

在 implementation 目录运行；已生成的summary不能覆盖，复查换output名：

```powershell
uv run --locked python -X utf8 scripts/aggregate_sft_scores.py `
  --recipe-dir ../experiments/sft_mini_v1/evaluation_recipe `
  --run-dir ../experiments/sft_mini_v1/results/b0_v1 `
  --reviews ../experiments/sft_mini_v1/results/b0_v1/scoring_v1/reviews.assistant.jsonl `
  --output ../experiments/sft_mini_v1/results/b0_v1/scoring_v1/summary.rerun.json
```

实际核对36条完整覆盖、来源hash、检查点逐字一致、引句确实在原始输出中、整题标签与冻结聚合逻辑一致，均通过。两个定向测试通过（0.05秒），验证消极约束不能补偿正向失败、不确定不被丢弃，以及不能篡改检查点、伪造引句或混用输出版本；没有重跑全项目。

首次辅助读取经Windows原生stdout传递中文时，复制到评分记录的检查点出现编码损坏；聚合器因与冻结原文不一致拒绝，未生成汇总。随后改用ASCII转义的结构化传递并重新核对，判定理由/标签不变，原始题目和模型输出未受影响。这是派生评分元数据的问题，不能用它解释模型输出中的重复或缺陷。原始运行的verification.json和result.json保留当时“评分待进行”状态，本轮评分另存，不回写历史证据。
