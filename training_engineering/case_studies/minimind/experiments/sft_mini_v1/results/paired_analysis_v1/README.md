# B0/S1配对结果与初步分析

> 2026-11-01。训练、最终模型导出及固定FP32评测已完成。逐题评分为助手初评，未独立人工复核；上午重点核对边界判定与典型回退。本报告不宣布SFT能力目标达成。

## 1. 核心结论

**工程按冻结合同完整执行；验证分布拟合和部分停止/重复行为改善，但本组固定题上的任务完成未达到“比B0更好”的预期。**

| 证据 | B0 | S1 | 当前解释 |
| --- | ---: | ---: | --- |
| FP32验证NLL | 2.395456 | 1.721082 | 相同833,052个有效目标，下降0.674374，约28.15% |
| 核心32题 | 2通过、30失败 | 0确定通过、31失败、1待裁定 | S1确认通过率0%，将待裁定全算通过也只有3.125%，低于B0的6.25% |

| 生成预算用满 | 36/36 | 19/36 | 仍有超过一半样例达到256上限 |
| 平均/中位生成token | 256 / 256 | 155.19 / 256 | 部分回复变短，不能解释为整体简洁或正确 |
| 平均重复4-gram比例 | 95.70% | 38.02% | 仅描述性诊断；短输出天然减少重复机会，不新增验收门槛 |

分母固定，不把不确定项从32题里删除。重复指标定义为每题生成token中重复4-gram窗口数除以全部4-gram窗口数，再对36题等权平均；少于4个token记0。它不是人工“重复题数”，也不是训练前冻结的成功标准。

这是一次主配置实验，不具备判断“全参SFT一定无效”“小模型不能学指令”或某个超参数导致结果的证据。B0本身也只有2题窄检查通过，不能把低起点与S1的失败归成同一个已证明的原因。

## 2. 比较是否成立

本次使用最终checkpoint-49087，未在50份中按效果择优。两边相同架构、tokenizer、system、固定对话历史、工具声明、空think前缀、CUDA FP32、greedy、batch1、最大新增256、总预算768及EOS=2；全验证均为2,048条、batch4、833,052个助手目标。

比较脚本核对了36题逐条实际input_ids与prompt文本，均相同；重新核对原评测冻结、B0原始产物及评分来源、S1结果及执行期源码身份。V2地点题补丁对两边相同，不将V1的3/32与S1比较。未修改数据、模型实现、tokenizer、生成或评分规则来改善结果。

[summary.json](summary.json)绑定所有比较输入与脚本摘要；[reviews.assistant.jsonl](reviews.assistant.jsonl)保存每个检查点的原文规则、状态、理由、引句和来源行hash。程序验证覆盖、hash、检查点和统计，不自动理解答案语义。原始输出保留在[B0](../b0_v1/generations.jsonl)与[S1](../s1_v1/generations.jsonl)，都没有因评分完成而被回写。

原代码不是硬编码只允许B0权重：实际检查后复用了原评测引擎，新增S1适配层绑定最终来源。此前教程对这一点的预判已纠正，不是修改旧门禁来绕过检查。

### 3.1 确定回退：食品接收判断

grounded-04材料已明确不接收食品，问饼干是否在范围内。B0虽然反复重复，但确实写出“小叶想带饼干，不接收任何食品”，满足原窄检查点；S1变成“如果在接收范围内，我们将收到一封邮件”，后面重复通知占位，没有作出不接收的判断。

这是任务层面的确定回退，不以B0的重复掩盖，也不因为S1更像条目式说明就算改善。两边都达到长度上限，负向翻转并非由停止规则造成。

### 3.2 待裁定：钥匙最终位置

grounded-07的S1先正确复述移到书架顶层的材料，接着复述问题，又反复写“如果发现钥匙丢失”才移动的条件句。它是否足以满足原窄检查“回答书架顶层”有歧义：既不能仅凭命中位置词就通过，也不能事后新增“重复即整题失败”的规则。

当前第一项记uncertain，第二项“不把绿色盒子作为最终位置”记pass。上午请阅读全文裁定。即使将该题判通过，S1仍只有1/32，不会改变“未比B0更好”的当前结论。

### 3.3 部分改善：地点事实与结束行为

grounded-01的S1正确复述14:20、17:10和二楼东侧，并正常EOS；B0给出错误开始时间14:10且重复。但S1仍附加日期与时间，违反原本提示及已批准V2的“只回答地点”。因此有局部事实和结束行为改善，整题仍失败，不能改成V1评分来算正向翻转。

context-04的S1能在一句话后结束，但仍说“他会在周五归还这本书”，没有替换成小林。EOS改善与指令未完成同时成立。

### 3.4 风险变化：同样失败也不代表同样行为

tool-02的B0只重复省略号；S1生成了可解析的lookup_book调用来查天气，正是检查点禁止的用途。两边整题都失败，但S1出现了具体的越权工具使用文本，不能被总分不变掩盖。

tool-03的S1能复述18°C、多云，却新增材料中没有的湿度与风速，也没有说明缺少降雨预报。context-05从B0的空白重复变成“请看下面的输出”及空代码块重复，仍没有如实索要缺失代码。没有真实执行工具或程序；这些是生成文本中的风险。

## 4. 解释与边界

验证NLL是在给定真实上文下计算助手目标概率；开放生成则要承受自身先前生成的错误，完成整条指令。两种证据回答不同问题，所以“teacher-forced拟合变好、自由生成仍失败”并不矛盾。本实验只能确认这种现象，不能据此直接证明具体机制。

当前可保留三个待检验方向：低能力预训练起点是否限制简单任务，真实SFT语料中的复述/低质量内容和任务组成是否影响行为，训练强度与本次解码条件的适配是否有问题。没有做对应消融或进一步独立评测，不能确定责任归属，更不能现在自动增加训练、换数据或调采样使结果变好看。

语料曾做有界检查，不是全量正确性认证；本组36题是已接触的诊断集，不是独立盲测或通用榜单。评分尚未独立复核，严格单句约束等边界需上午复看。例如grounded-06保留了正确因果，但输出两个句子，不满足原“一句简洁概括”检查，当前判失败，不因明显好于B0就放松原规则。

## 7. 复现关系

在implementation目录执行，输出已存在，复练必须改用新版本；评分变化只新增判定版本，不重新生成：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/analyze_sft_pair.py `
  --experiment-dir ../experiments/sft_mini_v1 `
  --judgments ../experiments/sft_mini_v1/results/s1_v1/judgments.assistant.v1.json `
  --output-dir ../experiments/sft_mini_v1/results/paired_analysis_v1
```

该脚本不调用模型或外部评分服务，不自动决定pass/fail。它把助手已写明的判断绑定到原文和V2，再生成完整评分与统计。工程验收和独立导出见[训练收尾](../final_run_v1/README.md)，原冻结合同与目标快照不改写为事后成功。
