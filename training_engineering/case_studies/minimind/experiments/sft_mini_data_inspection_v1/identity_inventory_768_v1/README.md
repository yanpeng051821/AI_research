## 2. 检索与分组

入口为 [inspect_sft_identity.py](../../../implementation/scripts/inspect_sft_identity.py)。先经已验证的来源对应读取器核对候选、行号和 hash，再查看消息的 `content` 与 `reasoning_content`。名称匹配覆盖所有角色，身份问题、助手措辞与 system 指令按角色分别记录；不扫描顶层元数据和 tools/tool_calls 载荷。

规则包含作者名、项目名、训练者名、有限的第三方名称，以及“你是谁”“我是”“我的训练数据”等中英文表达。完整表达式入报告。这是可复跑的检索，不是语义分类器：引用、角色扮演、礼貌用语、推理里的反问都可能命中，未列出的别名和间接表达可能漏掉。

互斥复核分组按固定优先级确定，每条命中记录只进一个桶：

| 分组 | 数量 |
| --- | ---: |
| 出现目标训练者名称 | 0 |
| 出现上游名称且同时命中身份措辞 | 15,992 |
| 出现上游名称但未命中身份措辞 | 4,616 |
| 出现其他名称且同时命中身份措辞 | 864 |
| 只有身份措辞、未命中所列名称 | 33,027 |
| 出现其他名称但未命中身份措辞 | 1,492 |

“同时命中”仅指同一条记录里共同出现，未保证同一字段或指向同一对象。“未命中身份措辞”也不能解释成客观引用；以下例子展示了边界。

## 3. 样例中的不同问题

固定种子 `20261031`，每个非空桶做容量 8 的蓄水池抽样，共保存 40 条完整记录。助手浏览了每桶前两条的部分字段，并完整查看下表的 687,392 与 692,204；不是人工验收全部 40 条，更不是估计全量错误率。

| 原始来源行 | 实际观察 | 对后续处理的意义 |
| ---: | --- | --- |
| 687,392 | 用户问是否会天天用 AI 开发算法，助手却只回答由个人开发者独立开发的 MiniMind 自我介绍，思考字段重复该介绍 | 不仅是身份归属，也答非所问；仅替换训练者名字不能修复，建议原样排除或完整重写后另审，本次未执行 |
| 49,237 | “作为 MiniMind”出现在思考里，却分到未命中身份措辞的桶 | 表明词法规则会漏掉身份表达，不能只改有身份 cue 的桶 |
| 692,204 | 用户明确设定虚构超级英雄“勇士水晶”，对话围绕该角色展开 | 从身份处理维度不能把角色姓名换成 yanpeng；不代表整条表达质量已通过 |
| 384,323 | 用通义千问/Qwen 举例说明预训练模型的文本生成 | 第三方名称不应因本模型训练者变化而替换；代码正确性未在本步核验 |
| 88,301 | 用户提到 Qwen，助手以英文礼貌用语 “I'm here to help” 开头 | 名称和自称词共同出现，不等于助手自认是 Qwen |

这一步让后续改写有具体对象，也说明不能用词命中直接生成改写动作。正文和思考中的自述要联动复核，用户的角色要求、客观介绍、引用和来源归属不能被全局替换。

## 4. 复跑与产物

在 `implementation` 目录使用 PowerShell；新路径避免覆盖本次产物：

```powershell
uv run --locked python scripts/inspect_sft_identity.py `
  --candidate-report ../experiments/sft_mini_data_inspection_v1/tool_quarantine_768_v1/report.json `
  --details-dir data/audit/sft_identity_inventory_768_rerun `
  --report-dir ../experiments/sft_mini_data_inspection_v1/identity_inventory_768_rerun `
  --sample-size 8 --seed 20261031
```

忽略目录 `implementation/data/audit/sft_identity_inventory_768_v1/` 保存：

- `review_index.jsonl`：55,991 条命中定位，包含原始来源行/hash、当前行号、字段和检索信号，约 22.34 MiB。
- `samples.jsonl`：40 条带来源的完整样例，95,308 字节。不是已清洗数据，也不是最终评测集。

[report.json](report.json)保存输入、代码、表达式、计数、抽样方法及上述文件的 hash；不把整份语料或大索引放进 Git。本次扫描约 91.84 秒。

浏览中文样例时曾遇到 Windows 标准输出的 GBK 编码错误，预览脚本导入 `sys` 后设置 `sys.stdout.reconfigure(encoding="utf-8", errors="backslashreplace")` 即可正常输出，没有因此改写数据。终端乱码和原文中的替换字符是两件事，不能仅凭控制台显示判断语料已损坏或已修复。
