# 身份表达的高频精确分组

## 1. 当前结论

本次基于上一版身份检索索引，按助手回复原文和思考字段原文分别分组，再关联用户问题及完整上下文。没有近似聚类、改写、排除或新建训练候选，当前数据仍是工具隔离后的 808,513 条。

| 范围 | 数量 |
| --- | ---: |
| 完整候选身份核验 | 808,513 条 |
| 身份检索索引记录 | 55,991 条 |
| 其中能选出相关助手轮次的记录 | 55,987 条 |
| 选中的助手轮次 | 69,970 次 |
| 非空回复出现次数 / 精确组数 | 69,969 / 60,960 |
| 非空思考出现次数 / 精确组数 | 44,906 / 37,305 |
| 回复正文含上游名称的精确组 | 5,621 组 |
| 这些上游名称回复出现次数 / 涉及记录 | 13,547 / 12,443 |
| 最高频 10 个上游回复组涉及记录 | 6,222 条 |

最高频 10 组覆盖约一半的上述 12,443 条记录，但不能解释为能安全自动改写一半。记录数、助手轮次数、字段出现次数和唯一文本数是不同口径；正文与思考的覆盖也不能相加。

## 3. 上下文反例

助手完整查看了下列三条对照记录；示例包还保留其他供复核的上下文，不将全部包内记录记为人工验收通过：

| 原始来源行 | 用户问题 | 分组观察 |
| ---: | --- | --- |
| 620,011 | 请求介绍阿里巴巴云的信息 | 返回第 1 组自我介绍，没有提供所问信息，不能只改名字 |
| 629,604 | “你叫什么名字，大模型？” | 返回第 3 组自我介绍，可作为直接身份问答修订候选；尚未执行 |
| 620,538 | “你和阿里云有什么关系？” | 属于归属相关问题，但未命中本版身份问题表达式；词法未命中不能直接当成无关任务 |

因此，高频组提供的是批量工作的入口，不是自动动作。第 1 组虽有 2,570 次未命中身份问题措辞，也不能据此宣布这 2,570 次全部答非所问；需要语义判法及明确的正反例。

## 4. 实现与复跑

[group_sft_identity_templates.py](../../../implementation/scripts/group_sft_identity_templates.py)复用固定的身份索引和来源对应读取器：

1. 核对候选报告、索引报告、索引 hash 和检索代码版本，遍历完整候选，验证索引行和原始来源相符。
2. 选中命中助手字段的轮次，以及命中用户字段后紧随的首个助手轮次；不到下一个 user 之后寻找，不重复计入同一轮次。仅 system/tool 字段命中时不自动选其他轮次。
3. 对非空 content 与 reasoning_content 分别计算精确文本 hash，不 strip、不合并近似句式。空正文不作为最大模板，工具动作也不因此判错。
4. 每组统计出现次数、不同记录、最近用户问题、完整前文、思考/回复对应字段及整条消息的变体。最近用户问题措辞仅作检索线索。
5. 每个问题措辞类别保留最早最多三个不同上下文的定位，供对比；对前 10 回复、前 10 思考及前 10 上游回复组，再提取去重后的 85 条完整上下文。

在 `implementation` 目录用 PowerShell 复跑，新路径避免覆盖：

```powershell
uv run --locked python scripts/group_sft_identity_templates.py `
  --candidate-report ../experiments/sft_mini_data_inspection_v1/tool_quarantine_768_v1/report.json `
  --inventory-report ../experiments/sft_mini_data_inspection_v1/identity_inventory_768_v1/report.json `
  --details-dir data/audit/sft_identity_groups_768_rerun `
  --report-dir ../experiments/sft_mini_data_inspection_v1/identity_template_groups_768_rerun `
  --top-k 10
```

## 5. 产物与验证

忽略目录 `implementation/data/audit/sft_identity_groups_768_v1/` 保存 `reply_groups.jsonl`、`reasoning_groups.jsonl` 和 `top_group_contexts.jsonl`。前两份保存完整分组文本和统计，后一份保存 85 条完整记录及对应分组链接；它们不是新训练集。例子是最早不同上下文的对照选择，不是随机或按比例抽样，不能估计质量比例。

[report.json](report.json)保存小型前十表、输入/代码/文件身份、统计与覆盖口径。本次约 17.01 秒。6 项定向测试覆盖相同回复的不同问题/思考/消息、次数与记录数区别、空白不合并、思考状态、轮次选择和例子边界；全项目 460 项通过（91.87 秒）。

独立只读复核重新遍历全部候选与固定索引，重算 60,960 个回复组、37,305 个思考组的出现次数和不同记录数，核对排序、文本 hash、前十覆盖以及 85 条完整上下文与原始内容，均一致。输入完整 hash 不变。这验证分组和产物对应，不代表自动语义判别可靠。

下一步优先审查高频组中的直接身份问答与被固定介绍覆盖的其他任务，分别讨论改写或隔离规则。未命中身份问题措辞不直接排除，已命中也不直接统一改写；正文、思考与用户约束须联合处理，修改后再验长度、重复和监督边界。
