# 768 长度候选的精确去重

## 1. 当前结论

本次对已完成长度筛选的 856,531 条记录执行精确对话去重：同一完整 `conversations` 只保留原始来源中最早出现的一条，单独另存重复项。没有改写对话、应用内容审核决定、修订身份或划分数据。

| 产物或统计 | 记录数 | 有效助手目标 |
| --- | ---: | ---: |
| 输入：768 长度候选 | 856,531 | 340,351,475 |
| 保留候选 | 809,713 | 334,943,065 |
| 精确重复排除项 | 46,818 | 5,408,410 |
| 逐条来源对应表 | 856,531 | 不作为训练数据 |

重复组为 8,632 个，组内记录共 55,450 条，最大组大小 804。每组第一条包含在保留候选中，不能把全部组内记录当成删除数量。`809,713 + 46,818 = 856,531`，两份输出的字节数与目标数合计也与输入一致。

这是长度候选上的实际结果，不同于[完整原始来源重复统计](../exact_duplicates_v1/README.md)的 46,862 条。最终候选仍需内容与协议处理、身份修订、同题分组隔离和切分验收。

## 2. 去重规则

键沿用 `conversation_sha256`：对完整 `conversations` 列表进行字典键排序、紧凑 JSON 序列化后计算 SHA256。消息顺序、全部消息字段、正文空白、思考和工具字段均保留；只有外层排版、字典键顺序与顶层非对话元数据不参与比较。

因此，相同问题但回答不同、回答相同但思考不同、工具声明不同等记录不会被此规则合并。字符串形式的工具 JSON 不额外解析为语义等价；未进行近似去重。若顶层元数据不同，本轮保留最早记录的原始元数据，其他记录仍完整另存，并非丢弃来源证据。

选择最早一条是为了确定性与可追溯，不是认定它的回答质量最高。对于同键记录，本规则认为训练用的完整对话相同；去重减少非预期重复加权，不证明内容正确。

## 3. 实现与数据流

入口为 [deduplicate_sft_subset.py](../../../implementation/scripts/deduplicate_sft_subset.py)。

1. 读取长度筛选报告和全量编码报告，检查两份报告的依赖 hash、768 整条排除规则以及当前编码路径身份。
2. 从全量编码明细中依次取出长度合格的行，逐条与实际长度候选的原始字节 hash 核对。由此得到候选行号到原始来源行号的对应，不能把筛选后的第 N 行误当原始第 N 行。
3. 按对话键建立 `first_seen`。第一次出现时写入保留文件并记录输出行号；再次出现时写入重复文件，指向此前保留的记录。不重新排序、不重新序列化训练记录。
4. 每条输入都写入 `lineage.jsonl`，包含输入行号、原始来源行号和行 hash、对话键、保留/排除动作，以及对应保留记录的输出行号和来源行号。
5. 核对输入、完整明细的 hash、数量和监督量后，发布最终命名文件；重新读取输出核对 hash，再保存完成报告。报告或身份验收不完整时，不能仅凭文件存在就继续使用。

在 `implementation` 目录用 PowerShell 复跑；本次目录已经存在，下面使用新目录以避免覆盖：

```powershell
uv run --locked python scripts/deduplicate_sft_subset.py `
  --length-report ../experiments/sft_mini_data_inspection_v1/length_selection_768_v1/report.json `
  --encoding-report ../experiments/sft_mini_data_inspection_v1/full_encoding_preflight_v1/report.json `
  --output-dir data/processed/sft_dedup_768_rerun `
  --report-dir ../experiments/sft_mini_data_inspection_v1/deduplication_768_rerun
```
