# 身份语料的 Luna 辅助审核

## 1. 当前结论

2026-10-31，按用户要求调用 `gpt-6-luna` 子 Agent，审核高频模板对应的 85 条完整对话。已完成首轮、反馈修订和主助手的来源核验，但语义抽查仍发现误读，**不能直接用于自动改写、排除或冻结数据**。候选仍为 808,513 条，没有生成新版本。

当前入口是[修订摘要](REVIEW_REVISED_SUMMARY.md)和[修订逐条建议](reviews.luna.revised.jsonl)。[首轮摘要](REVIEW_SUMMARY.md)及[首轮建议](reviews.luna.jsonl)仅保留审核过程，不能与修订版叠加计数或混作最终决定。

## 2. 审核方法

上一阶段按精确回复和思考文本分组，解决的是“同一句话出现多少次、对应哪些上下文”。本次进一步问：这句话是否回答了用户实际提出的问题？审查输入来自 `implementation/data/audit/sft_identity_groups_768_v1/top_group_contexts.jsonl`，每条包含完整对话、原始来源行和消息身份。

1. 子 Agent 联合阅读用户问题、助手正文与 `reasoning_content`，分别判断请求意图、响应程度、身份提及方式及建议动作。
2. 主助手核对输入 SHA256、记录覆盖、重复链接和消息身份，再抽查语义理由；来源核验通过不等于语义判断可靠。
3. 对首轮中把能力、爱好和使用方式一并当成身份问答的问题，要求子 Agent 保留初版，另写修订版。
4. 修订仍是 `assistant_proposal`，`user_review=pending`；确认判法后才能讨论派生数据处理，不把审核 JSONL 追加到训练对话中。

“只修身份”的判断标准是：只调整自我介绍中的身份事实后，是否仍能满足用户的主要要求。询问能力关键词、API 使用方式、技术原理或指定输出格式时，固定介绍通常不能替代实质回答。反过来，也不要求普通问候必须附带完整的模型说明。

`yanpeng` 是训练者，不因此成为模型名称。可以保留 MiniMind 名称并明确这是基于开源项目和作者架构的训练版本；第三方名称、引用和角色名也不全局替换。自己的预训练权重从随机初始化训练，不能写成接续官方预训练权重。

## 4. 主助手复核

### 4.1 来源核验

- 输入 SHA256：`b885d82eeeea7cbbb48095f373cc1dab20234bde0e06c25dd88a484bc0d17f3d`。
- 85 条输入含 177 个分组链接，去重后为 85 个助手轮次；两轮建议均覆盖全部轮次，无遗漏或重复。
- 逐条核对 `candidate_line`、`source_line_sha256`、消息索引和分组 hash；修订版还根据完整助手消息重新计算 canonical JSON SHA256，与 `message_sha256` 一致。
- 修订版文件 SHA256：`5dbf6dd63ff1f270badd54779381dc7692851ec6d818b34c4b4ec631e059324e`。

这些核验只证明“审核建议指向了正确记录”，不证明建议本身正确。没有为文档或审核记录变动重跑训练组件测试，也没有启动训练。

### 4.2 语义抽查与分歧

| 原始来源行 | 观察 | 当前处理 |

## 5. 后续衔接

先用直接身份、实质任务和歧义记录校准少量正反例，再决定哪些处理可以批量执行。对审核者误读和证据不准确的记录，需先修正理由或暂缓，不能因其标为高置信度就自动采用。完整重写、身份修订或排除经确认后，才另行生成派生版本，并复查长度、重复和监督边界。
