# 完整来源的精确对话重复检查

## 1. 当前结论

本次只读扫描原始候选 905,718 条，尚未叠加 768 长度筛选；没有删除、修订或划分数据。

| 指标 | 结果 | 含义 |
| --- | ---: | --- |
| 不同完整对话 | 858,856 | 按下述规范化键计算 |
| 重复组数 | 8,675 | 至少出现两次的对话组 |
| 重复组包含的全部记录 | 55,537 | 包含各组第一条 |
| 每组保留一条时的多余记录数 | 46,862 | 不包含各组第一条；尚未执行排除 |
| 最大组大小 | 804 | 同一完整对话在来源中出现的次数 |

`858,856 + 46,862 = 905,718`。不能把 46,862 与超长排除 49,187 简单相加：两种条件可能命中同一条记录。后续要对实际长度候选重新核算。

## 2. 方法与目的

入口为 [inspect_sft_duplicates.py](../../../implementation/scripts/inspect_sft_duplicates.py)。逐条基础校验后，取 `conversations` 列表，按字典键排序、紧凑 JSON 序列化并计算 SHA256；统计出现次数、第一条来源行号以及前 10 个重复行配对。扫描同时核对完整来源的字节数、数量和 SHA256。

这个键忽略外层 JSON 排版、字典键顺序及顶层非对话元数据，但保留消息顺序、每条消息的全部字段、正文空白和字符串内容。例如同一问题的两个不同回答不会被此规则当作精确重复；字符串形式的工具 JSON 也不会被额外解析成相同语义。

这样先明确精确重复的规模，再制定保留规则，并在切分时避免相同完整对话跨训练与验证集。检查没有覆盖近似重复、同题多回答的分组隔离、共享文档来源或工具参数语义等价；精确去重也不能独自保证没有泄漏。

## 3. 复跑与证据

在 `implementation` 目录运行，使用新输出目录以避免覆盖：

```powershell
uv run --locked python scripts/inspect_sft_duplicates.py `
  --source data/raw/minimind/sft_t2t_mini.jsonl `
  --source-report ../experiments/sft_mini_data_inspection_v1/full_structure_v1/structure_report.json `
  --report-dir ../experiments/sft_mini_data_inspection_v1/exact_duplicates_rerun
```

[report.json](report.json)保存来源、分析代码、来源报告 hash、计数和可定位的行号配对，不复制大段对话正文。4 项定向测试覆盖字典键顺序不影响身份、文本/消息顺序/思考字段差异保留、重复组计数、来源不变、身份不匹配和坏记录拒绝。

本报告只说明来源的精确重复，不给出内容质量合格率，也不代表用户已确认每组保留哪条。
