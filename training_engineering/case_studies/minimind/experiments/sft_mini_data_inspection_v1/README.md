## 3. 本地前缀检查

### 3.1 输入与方法

输入是 implementation/data/source_samples/sft_sample.jsonl，对应既有[样本来源清单](../../implementation/data/source_samples/manifest.json)。它是源文件前 20 条完整记录，不是随机抽样。

读取原始字节并核对 SHA256 后，用当前本地 tokenizer 和 `encode_sft_conversation` 对每条完整对话编码。不随机添加 system，不移除空思考段，不截断，不 padding。长度是模板编码后的 token 数；监督量按 labels[1:] 中非 -100 的数量统计，与 causal shift 后的目标口径一致。

本次只在终端运行读取与统计，没有改写源数据、训练代码或已冻结的预训练配方。该结果描述当前编码路径，不代替之后加入工具字段转换或不同思考规则后的重新审计。

## 4. 编码兼容性

官方 SFTDataset 除套模板外，还处理 system 消息携带的 tools，以及字符串形式的 tool_calls，将其转换后传给模板。此前本地编码器直接传入 messages，真实工具记录会触发模板异常；现在已新增 `prepare_sft_messages` 并接入 `encode_sft_conversation`：先基础校验、深复制，提取 tools 并解析 tool_calls，再分别传入模板。当前源格式中的 function 包装、名称、参数形态与字段位置有明确检查，不支持的输入报错而不静默丢弃。

适配函数不执行完整工具协议或内容质量审核，因此“可以编码”不等于“可以训练”。适配阶段先验证原有 20 条编码不变及 48 条分组样例成功，随后完成独立的完整来源逐条编码诊断；完整文件经 Hugging Face Datasets 统一字段后的 Dataset 载入仍未验收。阶段身份与测试见[适配验证](encoding_adapter_v1/README.md)和[全量预检](full_encoding_preflight_v1/README.md)，实现讲解见[教程第 3.5 节](../../practice_notes/week_08_sft_data_and_training.md#35-实现字段适配并接入编码器)。

官方还包含随机添加 system、按概率移除空思考段等处理。正式长度与监督量需要针对最终接受的编码规则统计，不能混用“原始模板长度”和“处理后训练长度”。现在不自动加入这些增强，也不擅自删去思考或工具数据。

## 5. 人工复核与身份说明

### 5.1 复核目标

本阶段不只是决定哪些记录排除，还要明确本轮希望模型学习的任务、消息字段与监督范围，再选择编码长度、超长处理和数据隔离规则。对话内容可能包含真实知识，也可能包含模板化自述、错误能力声明或不适合本模型的身份信息，不能因为格式合格就默认全部纳入训练。

2026-10-29 逐条查看本地前 20 条记录的用户问题后，发现内容以模型身份、训练来源与能力自述为开头，后续涉及日常闲聊、电影书籍、AI 与模型技术、隐私伦理和医疗应用等话题。这是人工归纳的话题，不是源文件提供的领域标签；不据此推断完整数据集的领域配比。

其中一条 reasoning_content 将“训练数据来源不能透露”当作既定规则，但这不适用于我们已经公开数据来源的实验；它应进入待复核项，而不是仅保留看起来流畅的文字。思考字段与最终回答都需要检查，不能把合成推理文字当作模型真实内部过程或质量保证。

### 5.2 身份改写请求

用户已确认使用 `yanpeng` 作为本轮模型训练者，并要求相关字段一致。本轮仅对明确、单轮且属于已知介绍的记录有限修订，最终保留 14 条；其余名称语境暂存，不宣称全部身份内容已改完。不修改原始 JSONL、已有样本哈希或上游归属说明。

后续对“你由谁训练/开发”这类身份相关内容逐条审核，在派生训练数据中统一说明。例如表述为：“我是 yanpeng 基于 MiniMind 开源项目及其作者提供的架构训练的小型语言模型。”涉及同一身份的用户上下文、助手回答和 reasoning_content 一并检查，避免字段间互相矛盾。本轮预训练权重来自自己的随机初始化训练；“基于 MiniMind”说明架构和工程参照，不写成加载过官方预训练权重。

不执行全局字符串替换。上游作者的客观介绍、引用、许可证和来源记录继续保留原作者名称；只改名字而保留虚构的训练来源、保密规则、实时能力或多模态能力声明，也不能算完成修正。若修改会影响后续轮次的上下文或思考字段，需要一起复核。

身份修改的审计记录应关联源记录 ID/内容 hash、消息索引、字段、动作、理由和修改后的内容身份。人工决定是生成派生数据的依据，不是追加到训练集的新对话；完成修改后重新编码、统计并产生新版本。

### 5.3 样本决定

当前只约定需要区分的处理动作，不表示已经判定完整数据：保留、排除、修订后保留、暂缓复核。按轮次处理时还要保留必要上下文；多轮记录中出现一条可修订的身份回答，不自动导致整条记录丢弃，也不自动意味着其他轮次全部合格。
