# 剧版盛明兰：中文日常对话 SFT 案例

> 第二个训练工程案例 · 更新：2026-09-24
> 状态：Gate 0 已暂停；公开剧版语料不足，基座未选，训练未启动。
> 结论：体验目标保留，但在数据与版本合同满足重启条件前不继续采集或训练。

## 目标

让一个可在本机部署的小模型，以剧版盛明兰的身份进行自然的中文日常对话，
并在较长的多轮交流中保持人物性格、关系和对话事实的一致性。

本次实验要回答：在已有模型和角色提示的基础上，针对性 SFT 能否改善角色日常对话，
并保留长对话中的一致性与本机运行的可用性。具体训练假设将在基线错误分析后确定。

本页作为项目入口，记录体验约定、工程流程和当前工作；详细执行合同在实验目录维护。

## 体验约定

| 项目 | 约定 |
| --- | --- |
| 剧集来源 | 《知否知否应是绿肥红瘦》电视剧版；小说内容需核对后才能引用 |
| 用户与关系 | 用户以本人身份交流，从初识开始，可以逐渐熟悉 |
| 聊天场景 | 日常生活与情绪交流，保留明兰的人物经历和表达习惯 |
| 现代话题 | 允许用户谈论现代生活；角色可以询问并理解用户解释的概念 |
| 人物时期 | 每次会话保持稳定的时期设定，具体选择由阶段 1 确定 |
| 首版范围 | 单角色、中文文字聊天，先验证当前会话记忆 |
| 使用范围 | 非商业学习与体验；数据使用条件、原始语料及模型产物发布范围分别核验 |

跨会话长期记忆和可切换的人生阶段留待后续讨论。

## 训练工程

B0 是选定模型在训练前的基线，S1 是本次 SFT 后的模型。先测量 B0 的具体问题，
再决定数据与训练改动，最后检验改善是否成立。

| 阶段 | 要完成的工作 | 留下的产物 |
| --- | --- | --- |
| 1. 人物与场景 | 整理剧集证据，明确默认时期、关系与场景 | 人物证据表、角色规范 |
| 2. 模型与基线 | 设计开发场景和独立测试场景，比较少量候选模型，分析 B0 的主要失败 | 模型选择理由、B0 输出、速度与资源记录、训练假设 |
| 3. 数据与合同 | 构造并审查多轮 SFT 数据，确定切分、训练设置及预算 | 冻结的数据产物、实验合同 |
| 4. 分阶段训练 | 本地测试、GPU smoke、pilot，通过后才进行正式 LoRA SFT | 测试结果、S1 adapter、配置和训练日志 |
| 5. 评测与交付 | B0/S1 配对比较、匿名体验对比、本机部署及错误分析 | 评测报告、部署记录、成本与归档清单 |

### 实验原则

- 角色提示在开发集上完善后冻结；B0/S1 使用相同提示、推理精度、解码预算和评测协议。
- 训练、验证与测试按场景及来源片段分组隔离，避免同一剧情的改写泄漏。
- 最终测试不用于调整提示、筛选训练样本或修改验收标准。

### 评测原则

评测覆盖设定一致性、性格与表达、多轮事实记忆、匿名体验偏好，以及重复、截断和时延。
量表需描述可观察行为并记录评分理由；模型 Judge 经人工校准后用于辅助判断。
训练前冻结样本量与成功阈值，结果分别报告改善与退化，避免总体分数掩盖某项能力下降。

## 门禁结果

本案例的[Gate 0 决策](00_GATE0_DECISION.md)为暂停。语料采集已经证明：公开网页难以提供
完整、自然、带说话人归属的剧版中文对话；小说材料又会引入版本差异，不能作为同一角色数据
直接混入。当前不进入基座评测、数据集构造或 GPU 训练。

已整理的[人物证据表初稿](01_CHARACTER_EVIDENCE.md)继续作为研究材料保留。Luna 检索四条线索，
主助手筛选后保留三条；当前仅完成分集梗概核对，视频与措辞尚待核验，不构成冻结角色规范。

阶段 1 的目标是将“像明兰”的直觉整理成有剧集证据支持的判断标准。
产物统一称为“人物证据表”。学习者判断人物表现，助手协助核验来源。
可以先描述记得的片段，再补充集数与来源。

每个场景都按“发生了什么、她怎样回应、为什么这样理解人物、怎样测试”整理：

| 字段 | 内容 |
| --- | --- |
| 来源 | 电视剧版本、集数/时间点或可回看的链接；不确定的标待核验 |
| 情境 | 人生时期、对话对象、关系、发生了什么 |
| 可观察表现 | 实际言行的简要概括，不把猜测写成原剧情 |
| 人物解释 | 由言行推导的性格或表达规律，注明这是解释 |
| 适用边界 | 对不同身份、处境或时期是否可能有不同表现 |
| 新情境测试 | 没有复用原剧情台词的日常聊天问题 |

优先观察安慰他人、面对委屈、处理冲突、表达亲近、面对不了解的事情等场景。
这些是观察维度，不是已经证实的明兰性格标签。助手生成的示例不能作为剧情证据。

若未来满足重启条件，人物判断仍需做到来源可追溯、适用边界清楚，并能据此选择默认时期和
设计开发场景；完成后才进入阶段 2，使用冻结角色规范比较候选模型。

## 技术与待定项

本机部署以 8GB 显卡为约束。上下文暂按 8K 启动检查、16K 初步验证、32K 按需探测安排；
长度包含角色设定、历史消息和生成内容，能否达到目标由显存、速度与记忆实测决定。
MiniCPM5-2B 是候选，选型依据是实际角色对话表现与运行成本。

后续按阶段冻结以下事项：

- 模型：基座、revision、推理格式与上下文预算。
- 数据：语料来源及使用条件、样本量、长度分布与数据切分。
- 训练：LoRA 配置、训练预算与停止条件。
- 评测：量表、样本量、成功阈值及生成配置。
- 费用：训练、推理评测及其他服务的总预算上限。
