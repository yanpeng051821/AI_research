# 海光平台模型训练实习

> 目标：使用公开数据，复用现成工具走通训练与评测，为团队后续专用模型训练沉淀可复用经验。
> 状态：方案准备；BW1000 实机、数据和实验均未验收。更新：2026-10-21。

## 课题定位

当前没有内部测试数据，实习为长期安排。先用 MiniMind dense 学习训练流程，
再用公开软件任务做领域 SFT；不把“跑完所有训练算法”作为结题要求。

推荐的任务候选是 CodeXGLUE/Devign 代码缺陷二分类，需在 Demo 0 经导师确认。
它有函数代码和分类标签，适合建立可客观评测的小实验；它不是测试生成或失败日志根因分析。
MiniMind 是教学载体，也不预设为最终业务模型。

优先调用官方入口、团队现有脚本和成熟框架；缺少的运行包由课题准备方整理并验证后交付。
[工具交付清单](CONTRACTS.md#toolkit)会区分已有、待验证和待准备；命令范例不代表已在海光运行。

## 阶段路线

1. **D0 任务与工作区**：确定目标、存储、版本和责任人。
2. **D1 海光环境**：查卡与显存，完成小模型更新和数值检查。
3. **D2 小规模预训练**：处理公开文本，先做基线，再运行 smoke 和训练后评测。
4. **D3A 训练观测**：运行已有观察工具，识别上游 loss、累积与日志口径。
5. **D3B 恢复验证**：验证现成入口的保存与续训，明确功能恢复和严格等价的边界。
6. **D4 扩大预训练**：先 pilot 测资源，再按批准预算训练；学习一个受控对照。
7. **D5 通用 SFT**：处理消息与监督区间，完成 PT → SFT 的阶段交接。
8. **D6 缺陷分类**：用已验证的成熟框架完成 B0 → SFT → 配对分析。
9. **D7 阶段选择**：依据错误分析选择下一步，不强制 CPT、DPO 或 RL。

D2 的短 smoke 不依赖严格等价恢复；D4 的长任务必须先验证实际入口的功能恢复。
D4 的“全量”指指定数据版本的 train 全量，是否执行由 pilot 与预算决定。
D5 可从已经验收的小规模预训练产物开始，无需为了进入 SFT 强行跑完大文件。

## 工程衔接

MiniMind 阶段复用官方模型、Dataset 和训练入口，执行现成诊断与测试，记录实际行为。
遇到工具缺口交给导师/平台同事处理；从零搭训练器、手写算子、重写审计脚本都不属于实习任务。

领域 SFT 默认采用经 BW1000 验证的成熟框架，例如兼容版本的 Transformers/PEFT
或 LLaMA-Factory，具体选择在 D6 冻结。迁移的是数据合同、正确性测试、恢复检查和评测方法，
不要求把 MiniMind 的训练循环原封不动搬过去。更换框架后必须重新完成对应检查。

## 团队交付

每轮实验除了结果，还更新同一个 `reports/team_handoff.md`：

1. **环境配方**：已验证的设备、镜像、依赖与不支持项。
2. **数据配方**：来源、格式、处理参数、质量检查与适用范围。
3. **运行配方**：启动、观测、保存、恢复和评测的实际命令。
4. **故障记录**：症状、原因、解决方法和验证证据。
5. **迁移边界**：下一次专用模型训练可复用什么，哪些必须重新确认。
6. **交接验证**：另一位成员按记录重跑小型 smoke 的结果。

成功不只看模型分数，也看团队是否能不依赖原执行者重新运行。
这不要求公开公司数据；内部产物按团队权限和存储规范管理。

只维护这一份进度表，引用验收证据。本文保持路线，不复制不断变化的运行结果。
