# 小模型工具调用后训练

> 第三个训练工程案例 · 建立：2026-09-24
>
> **状态：Gate 0，任务、数据、评测和基座尚未冻结。**
>
> **当前动作：审计训练数据与 BFCL 评测的可执行性；GPU 不得启动。**

## 总结

本案例以小模型工具调用为受控任务，建立从基座评测、SFT/LoRA、偏好优化到
可验证强化学习和多轮 Agent 的连续后训练实验链路。每个阶段只有在数据、指标、
成本和停止条件通过门禁后才能启动，不把长期方向误写成已经冻结的训练计划。

当前只推进 Gate 0：确认是否存在许可清楚、质量可审计的训练数据，以及可在本地
先跑通的独立评测。基座模型、数据集、算法、训练预算和 GPU 配置均未决定。

## 目标

工具调用任务给模型一条用户请求和一组工具定义，要求模型选择正确工具、生成合法参数，
或者在不应调用工具时保持不调用。它提供了比开放式角色对话更明确的输入、输出和成功条件，
并可自然扩展到执行结果奖励与多轮环境交互。

本案例最终希望回答：

- SFT/LoRA 是否真正改善工具选择、参数生成和无工具判断，而不只是格式模仿？
- 哪些提升来自数据规模、接口格式或训练方法？
- 偏好优化是否能减少典型失败，而不是重复 SFT 已完成的工作？
- 当工具结果可执行验证时，RLVR 是否比离线监督提供额外收益？
- 单轮能力何时足以扩展到多轮、多步骤和错误恢复？

## 路线

| 阶段 | 核心问题 | 进入条件 | 主要产物 |
| --- | --- | --- | --- |
| Gate 0：任务审计 | 数据、评测、基座和成本是否支持可信实验 | 当前阶段 | 来源审计、污染边界、候选基座与预算 |
| B0：基座评测 | 未训练模型具体错在哪里 | Gate 0 通过 | 冻结评测合同、逐样本输出、错误分类 |
| S1：SFT/LoRA | 受控监督训练能否改善目标能力 | B0 可复现，训练合同冻结 | adapter/checkpoint、日志、B0/S1 配对分析 |
| P1：偏好优化 | 哪类偏好数据能修复 S1 残留问题 | S1 错误能转化为可信偏好对 | DPO 或其他选定方法的对照与消融 |
| R1：RLVR | 可执行奖励是否带来离线监督之外的收益 | 奖励可靠且环境可重复 | 奖励审计、训练轨迹、S1/P1/R1 对照 |
| A1：多轮 Agent | 单轮工具能力能否迁移到状态化任务 | 单轮评测稳定，多轮环境已冻结 | 多轮任务、错误恢复与成本分析 |

路线表示依赖关系，不表示 DPO、RLVR 和 Agent 已获准执行。任何阶段都可以因证据不足、
成本过高或无法公平比较而停止。

## 门禁

Gate 0 至少需要冻结以下内容：

- 任务边界：首轮只测哪些工具调用能力，明确不测哪些 Agent 能力。
- 数据条件：来源、许可证或使用条款、生成方式、字段、规模、质量和重复情况。
- 评测条件：独立测试集、污染风险、评分逻辑、逐样本输出和本地运行成本。
- 基座条件：候选模型的许可证、工具格式、上下文预算、本地 smoke 与服务器显存需求。
- 实验条件：B0/S1 唯一变量、成功阈值、回归指标、预算上限和停止条件。

在这些条件完成前，不创建正式训练配置，不上传服务器，不申请 GPU。

## 边界

- 正式实验优先复用 TRL、Transformers 和 Accelerate；不为证明能力重写完整训练框架。
- 对 loss、mask、数据合同、恢复和评测等关键行为保留最小独立测试与数值对照。
- BFCL 等外部评测只作为候选，必须先确认版本、运行方式和训练污染边界。
- 通用工具数据可以建立首个 baseline；运维和测试工具属于后续领域化分支，不在 Gate 0 混入。
- CS336 只作为按需基础补强，不替代本案例的后训练实验主线。
