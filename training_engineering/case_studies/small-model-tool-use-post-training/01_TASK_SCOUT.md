# 任务侦察

> 状态：进行中
>
> 目的：判断小模型工具调用是否具备可训练、可评测、可承担的实验条件。

## 当前进展

2026-09-26 已完成来源初查、xLAM 与 ToolACE 固定版本的全量结构统计、分散抽样人工复核，
并对固定 BFCL V4 三类做精确与字符串近似重叠检查和评分核心探针。MiniCPM Tool-Use 只下载并检查了
一个分片。尚未完成全量语义质量审计、更广义的语义/模板污染审计、BFCL 完整 CLI 运行、模型 B0 推理
或 GPU 资源测量；不能据此给出 `GO`。脚本与证据位于
`small_model_post_training/experiments/tool_use_gate0/`。

首轮工作问题：在冻结工具接口、提示和评测条件后，监督微调能否改善小模型的单轮工具选择
与参数生成，同时控制无相关工具时的误调用？SFT 是训练目标/方法，LoRA 是候选参数更新方式，
二者不是互斥算法。模型名称、训练数据版本和量化方式仍待决定。

这里的“单工具调用”指一次输出至多一个调用，输入可以包含多个候选工具。模型生成调用请求，
程序负责执行工具；首轮不要求模型根据工具返回结果继续规划。输出序列化格式须与所选模型
的 tool template 和评测 handler 对齐，目前不固定为自定义 JSON 或 `no-call` 字符串。

### 选用建议

当前先以 xLAM 的单调用子集作为 T1 主候选，ToolACE 作为 T2 补充候选，MiniCPM 多轮轨迹保留。
这是审计优先级，尚未批准训练或冻结混合比例。

固定版本 xLAM 的 60,000 条记录均可解码 `tools/answers`：28,461 条答案包含一次调用，
其中 20,438 条输入包含多个候选工具；31,539 条包含多次调用；空调用答案为 0 条。
单轮请求与单次调用是两个维度，不能把整个 xLAM 当作单调用数据。

ToolACE 下载后共有 11,300 条，字段为 `system/conversations`。其中 10,782 条使用可解析的
标准工具列表：首轮回复 9,179 条以调用格式开头，1,598 条为非空文字回复，5 条为空。
另有 518 条使用其他工具描述/调用格式，包含以 `{...}` 等形式发起的调用；先前把
所有非 `[` 前缀回复当作 1,988 条“不调用”样本的口径是错误的。标准格式文字回复中
分散抽取 24 条并检查工具定义：14 条可保留作进一步候选，6 条应剔除，4 条需另定规则；
14 条里只有 5 条属于“无相关工具”，其余 9 条是“缺必需参数而追问”。例如第 2805 条
误把可选参数当必填，第 1898 与 11289 条因没有工具而拒答本可直接回答的问题。
这些复核数量不能外推成全量可训练数量。

xLAM 的 28,461 条单调用记录中，28,057 条通过本轮结构、重复工具名和完全重复行检查；
20,104 条还包含多个候选工具。结构检查不是语义正确性保证：抽查第 28589 条编造了
未给出的赛事 ID，第 39504 条用无法按国家过滤的工具回答菲律宾新闻请求，第 23832 条
对“过去 30 分钟”的参数映射仍需判断。固定 BFCL 的 `simple_python` 中有 2 个问题与
xLAM 完全相同，涉及 xLAM 第 28987、42043、44567、56857、27613 行，后续子集必须排除。
在本轮比较的三个 BFCL 类别中，ToolACE 没有完全相同的问题；工具名重叠存在，但不等于
答案泄漏。近似字符串扫描（`rapidfuzz.fuzz.ratio >= 85`）检索到 321 对问题，覆盖
342 条 xLAM 和 1 条 ToolACE 源记录，其中包含上述精确匹配。首轮候选子集暂按保守规则
排除这 343 条，并在子集物化前冻结源版本、阈值与排除行号；这不是对剩余数据无污染的证明。
精确无交集也不能排除改写、模板与教师模型污染。
若混合来源，要同时考虑 ToolACE 正例，统一格式并检查来源偏差，避免模型通过数据来源特征
猜测是否调用。MiniMind、CS336 等学习材料与训练框架属于实现参考，不代替任务数据的覆盖审计。

### 评测范围

固定 commit 的 BFCL V4 中，`simple_python` 有 400 条；`multiple` 有 200 条，
每条给 2–4 个候选工具、正确答案只调用 1 个；`irrelevance` 有 240 条。
这与当前 [TEST_CATEGORIES.md](https://github.com/ShishirPatil/gorilla/blob/main/berkeley-function-call-leaderboard/TEST_CATEGORIES.md)
对 `multiple` 的文字简述不一致，实际以固定版本的数据和评分代码为准。
`irrelevance` 只判模型是否发起工具调用，不判文字回答是否有帮助。
固定版本官方解析器与 AST 检查器的 6 个合成正反例均按预期判定；这是评分核心探针，
还不是完整 BFCL CLI，也不是 B0。最终样本 ID、生成 handler 和成本仍待冻结。

开发探针用于调试 handler 与选择基座，最终保留集在探针之前划定，不参与调提示和选模型。
主指标优先使用所选类别的官方整条调用正确率；格式、函数名、参数错误作为辅助诊断，
不调用样本另外报告误调用率。额外做普通指令回归，成功阈值在开发探针后、正式 S1 前冻结。

## 结论条件

本阶段不选“看起来最强”的数据集或模型，而是回答是否能够建立一个公平、可执行、成本可控的
B0/S1 对照。最终必须给出以下一种结论：

- `GO`：任务、数据、评测和成本均可冻结，可以建立实验合同。
- `REVISE`：方向可行，但必须缩小能力范围、更换数据或更换评测。
- `STOP`：独立性、许可证、执行成本或提升空间不足，不进入训练。

## 任务边界

首轮候选能力按从简单到复杂分层：

| 层级 | 能力 | 首轮状态 |
| --- | --- | --- |
| T1 | 单轮、从一个或多个候选工具中选一个并生成参数 | 候选主任务 |
| T2 | 无相关工具时拒绝调用 | 候选主任务 |
| T3 | 单轮并行或多工具调用 | 待成本审计 |
| T4 | 多轮、多步骤、状态变化 | 后续阶段，不进入首轮训练 |
| T5 | Web、记忆、错误恢复等 Agentic 任务 | 后续阶段，不进入首轮训练 |

首轮应优先冻结 T1/T2。只有这两层能够稳定评测，才讨论更高层能力。

## 数据候选

### xLAM Function Calling 60K

官方数据卡称其约含 60K 条合成工具调用记录，覆盖 3,673 个可执行 API 和 21 个类别，
由 APIGen 配合多个模型生成。它是首个训练数据候选，但尚未通过审计。

- 来源：[Salesforce/xlam-function-calling-60k](https://huggingface.co/datasets/Salesforce/xlam-function-calling-60k)
- 需要核对：访问条款、许可证字段、原始 schema、答案可执行性和已修复问题。
- 需要统计：单/多工具、参数类型、无调用样本、语言、长度、重复和类别分布。
- 需要抽查：工具定义与答案是否一致、参数是否可解析、生成模板是否单一。

### ToolACE

ToolACE 提供工具学习数据生成方法和公开论文，可作为数据与生成流程对照。当前不默认采用，
需要先确认官方数据入口、许可证、版本和复现仓库之间的边界。

- 论文：[ToolACE](https://arxiv.org/abs/2409.00920)
- 需要核对：官方实现与第三方复现、数据可获得性、生成和验证机制。

### MiniCPM UltraData-SFT-Agent-2609

官方发布了 `Tool-Use`、`Search-Agent`、`Code-Agent` 和 `General-Agent` 四类数据。
首轮只考虑 `Tool-Use`，并从中筛选与 T1/T2 匹配的单轮目标；其他类别作为后续任务研究资料。

- 来源：[openbmb/UltraData-SFT-Agent-2609](https://huggingface.co/datasets/openbmb/UltraData-SFT-Agent-2609)。
- 需要统计：多轮长度、首个用户请求后的目标、每条轨迹的工具数量、assistant 每轮调用数、
  无调用比例、不同 `source` 的质量及重复情况。
- 需要检查首个用户轮次与工具调用之间的轮次分布；对后续轮次的调用，只有能还原冻结的
  单轮输入且不泄漏工具返回时才考虑纳入 T1。
- 需要核对：公开版本、上游数据来源与许可、具体工具格式、脱敏情况和 BFCL 污染边界。
- 数据卡明确说明静态轨迹不附带工具实现及可重放环境；不能把发布方验证描述当作本地可复验结果。

### 自建子集

若公开数据质量或范围不适合首轮实验，可从许可允许的数据中构建冻结子集；但不得在看过最终
测试答案后按模型表现挑选训练样本。所有筛选规则必须先由 schema、质量和任务范围决定。

## 评测候选

BFCL 是当前主要候选。公开说明覆盖单轮、多轮、多步骤及 Agentic 工具调用，并提供评测代码
和逐类任务。首轮不默认运行完整 BFCL V4，而是先确认最小独立子集。

- 项目：[Berkeley Function-Calling Leaderboard](https://gorilla.cs.berkeley.edu/leaderboard)
- 代码与数据：[BFCL GitHub](https://github.com/ShishirPatil/gorilla)
- 需要冻结：仓库 commit、BFCL 版本、子集、模型 handler、生成参数和评分脚本。
- 需要验证：本地能否运行、是否依赖付费服务、单样本输出能否落盘、失败是否可解释。
- 需要隔离：评测数据、工具定义和近似模板不得进入训练或数据筛选逻辑。

评测至少需要区分：

- 函数名错误；
- 参数缺失、多余、类型或取值错误；
- JSON/AST 不可解析；
- 应调用但未调用；
- 不应调用却调用；
- 总体正确率相同但样本发生正负翻转。

## 基座候选

当前不指定模型。候选必须同时满足：

- 权重和许可证允许本次研究与计划中的产物保存；
- tokenizer/chat template/tool schema 行为可检查；
- 参数规模支持可承担的本地或短时服务器推理与 tiny smoke；
- 服务器上可用单卡完成 LoRA 或所选 SFT；
- B0 在主任务上不是接近零，也没有接近饱和；
- 能使用相同生成接口完成 B0/S1 配对评测。

模型选择由 B0 探针决定，不因榜单名次、参数量或新旧程度直接决定。

## 污染审计

工具调用数据常由公开 API schema、模型生成和现有 benchmark 启发得到。审计必须检查：

- train/test 中工具名、描述和 query 的精确与近似重复；
- 同一模板只替换实体造成的伪多样性；
- 评测工具定义是否出现在训练数据；
- 生成数据使用的教师模型是否接触过评测；
- 去重只按文本还是同时按结构化语义；
- 数据筛选是否使用了最终测试表现。

无法证明“完全无污染”时，应明确可验证到什么程度，并限制最终结论。

## 成本审计

付费探针前先冻结费用上限、样本范围和停止条件；探针测量结果再用于正式训练预算。需要得到：

- 当前 Mac 的数据审计、格式转换和评分检查耗时，以及候选推理设备上的最小评测耗时；
- 目标序列长度和长度分布；
- longest-sample 与 first-batch 显存探针；
- LoRA/full fine-tuning 的显存估算；
- smoke、pilot、正式训练与评测的分别预算；
- 超时、OOM、评测过慢和产物上传的停止条件。
