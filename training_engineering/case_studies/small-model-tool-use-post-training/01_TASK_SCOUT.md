# 任务侦察

> 状态：进行中
>
> 目的：判断小模型工具调用是否具备可训练、可评测、可承担的实验条件。

## 结论条件

本阶段不选“看起来最强”的数据集或模型，而是回答是否能够建立一个公平、可执行、成本可控的
B0/S1 对照。最终必须给出以下一种结论：

- `GO`：任务、数据、评测和成本均可冻结，可以建立实验合同。
- `REVISE`：方向可行，但必须缩小能力范围、更换数据或更换评测。
- `STOP`：独立性、许可证、执行成本或提升空间不足，不进入训练。

## 任务边界

首轮候选能力按从简单到复杂分层：

| 层级 | 能力 | 首轮状态 |
| --- | --- | --- |
| T1 | 单轮、单工具选择与参数生成 | 候选主任务 |
| T2 | 无相关工具时拒绝调用 | 候选主任务 |
| T3 | 单轮并行或多工具调用 | 待成本审计 |
| T4 | 多轮、多步骤、状态变化 | 后续阶段，不进入首轮训练 |
| T5 | Web、记忆、错误恢复等 Agentic 任务 | 后续阶段，不进入首轮训练 |

首轮应优先冻结 T1/T2。只有这两层能够稳定评测，才讨论更高层能力。

## 数据候选

### xLAM Function Calling 60K

官方数据卡称其约含 60K 条合成工具调用记录，覆盖 3,673 个可执行 API 和 21 个类别，
由 APIGen 配合多个模型生成。它是首个训练数据候选，但尚未通过审计。

- 来源：[Salesforce/xlam-function-calling-60k](https://huggingface.co/datasets/Salesforce/xlam-function-calling-60k)
- 需要核对：访问条款、许可证字段、原始 schema、答案可执行性和已修复问题。
- 需要统计：单/多工具、参数类型、无调用样本、语言、长度、重复和类别分布。
- 需要抽查：工具定义与答案是否一致、参数是否可解析、生成模板是否单一。

### ToolACE

ToolACE 提供工具学习数据生成方法和公开论文，可作为数据与生成流程对照。当前不默认采用，
需要先确认官方数据入口、许可证、版本和复现仓库之间的边界。

- 论文：[ToolACE](https://arxiv.org/abs/2409.00920)
- 需要核对：官方实现与第三方复现、数据可获得性、生成和验证机制。

### 自建子集

若公开数据质量或范围不适合首轮实验，可从许可允许的数据中构建冻结子集；但不得在看过最终
测试答案后按模型表现挑选训练样本。所有筛选规则必须先由 schema、质量和任务范围决定。

## 评测候选

BFCL 是当前主要候选。公开说明覆盖单轮、多轮、多步骤及 Agentic 工具调用，并提供评测代码
和逐类任务。首轮不默认运行完整 BFCL V4，而是先确认最小独立子集。

- 项目：[Berkeley Function-Calling Leaderboard](https://gorilla.cs.berkeley.edu/leaderboard)
- 代码与数据：[BFCL GitHub](https://github.com/ShishirPatil/gorilla)
- 需要冻结：仓库 commit、BFCL 版本、子集、模型 handler、生成参数和评分脚本。
- 需要验证：本地能否运行、是否依赖付费服务、单样本输出能否落盘、失败是否可解释。
- 需要隔离：评测数据、工具定义和近似模板不得进入训练或数据筛选逻辑。

评测至少需要区分：

- 函数名错误；
- 参数缺失、多余、类型或取值错误；
- JSON/AST 不可解析；
- 应调用但未调用；
- 不应调用却调用；
- 总体正确率相同但样本发生正负翻转。

## 基座候选

当前不指定模型。候选必须同时满足：

- 权重和许可证允许本次研究与计划中的产物保存；
- tokenizer/chat template/tool schema 行为可检查；
- 参数规模支持本地量化推理和 tiny smoke；
- 服务器上可用单卡完成 LoRA 或所选 SFT；
- B0 在主任务上不是接近零，也没有接近饱和；
- 能使用相同生成接口完成 B0/S1 配对评测。

模型选择由 B0 探针决定，不因榜单名次、参数量或新旧程度直接决定。

## 污染审计

工具调用数据常由公开 API schema、模型生成和现有 benchmark 启发得到。审计必须检查：

- train/test 中工具名、描述和 query 的精确与近似重复；
- 同一模板只替换实体造成的伪多样性；
- 评测工具定义是否出现在训练数据；
- 生成数据使用的教师模型是否接触过评测；
- 去重只按文本还是同时按结构化语义；
- 数据筛选是否使用了最终测试表现。

无法证明“完全无污染”时，应明确可验证到什么程度，并限制最终结论。

## 成本审计

GPU 申请前需要得到：

- 本地 CPU/8GB GPU 的数据审计、格式转换和最小评测耗时；
- 目标序列长度和长度分布；
- longest-sample 与 first-batch 显存探针；
- LoRA/full fine-tuning 的显存估算；
- smoke、pilot、正式训练与评测的分别预算；
- 超时、OOM、评测过慢和产物上传的停止条件。

## 产物

Gate 0 完成时应留下：

1. 候选来源及许可证/条款记录；
2. 数据 schema、统计、抽样与质量问题；
3. BFCL 最小评测的本地运行证据；
4. 候选模型 B0 探针和资源记录；
5. 数据与评测污染分析；
6. `GO / REVISE / STOP` 决策及理由；
7. 若为 `GO`，下一阶段唯一实验问题和预算上限。

在这些产物完成前，本案例仍处于研究侦察，不是已批准的训练任务。
