# QLoRA：量化存储与训练计算

整理：2026-11-07。本文承接 LoRA，沿“剩余显存开销 → 存储与计算精度 → NF4 → 双重量化 → 分页优化器 → 训练与工程选择”展开。

[目录](README.md) · 前篇：[LoRA](01_LORA_STRUCTURE_AND_UPDATES.md) · 前置：[数值精度](../03_optimization/02_NUMERICAL_PRECISION_AND_MIXED_PRECISION.md)

## 1. LoRA 之后，还需要解决什么

- LoRA 减少可训练参数及对应梯度、优化器状态，但原模型仍要参与前向和反向中的必要计算。
- 冻结不等于删除：原基模权重仍占存储，训练还需要激活与临时计算空间。
- QLoRA 的核心是量化保存冻结基模，计算时使用反量化后的近似值，并继续训练浮点 LoRA 参数。
- 原论文还配合 NF4、双重量化和分页优化器，分别处理数值表示、辅助信息开销和显存峰值。

### 1.1 三种方案的定位

| 比较项 | 本篇所指的全量浮点微调 | 浮点基模 LoRA | QLoRA 核心方案 |
| --- | --- | --- | --- |
| 更新对象 | 全部原模型参数 | 新增 A/B；其他更新需另声明 | 新增 A/B；其他更新需另声明 |
| 基模主要权重存储 | 浮点 | 浮点，冻结 | 低位量化，冻结 |
| 新增 LoRA 参数 | 不需要 | 浮点保存和训练 | 浮点保存和训练 |
| 主要节省项 | 此处不专门压缩 | 可训练参数、相应梯度和状态 | 再压缩冻结基模权重及量化辅助信息 |
| 基模是否仍参与计算 | 是 | 是 | 是，使用反量化近似值 |
| 特有风险 | 完整更新成本较大 | 受挂载范围与低秩表示约束 | 再增加量化误差和算子兼容问题 |

这些方式可以服务于同一个 SFT 任务；表中不是三个必然依次执行的训练阶段。

## 2. 存储精度与计算精度分开看

### 2.1 不同对象可以使用不同精度

| 对象 | QLoRA 中的作用 | 本轮需要记住的精度关系 |
| --- | --- | --- |
| 量化基模权重 | 固定的原分支 | 主要权重以 NF4 编码及量化状态保存 |
| 反量化后的权重 | 运算所需近似值 | 转为计算精度，不是原值的无损恢复 |
| LoRA A/B | 可训练调整分支 | 使用浮点；不按冻结基模的 NF4 方式更新 |
| 激活和中间结果 | 前向、反向所需 | 不是因为基模 4-bit 就自动全变成 4-bit |
| 梯度 | 学习信号 | 与具体混合精度和参数配置有关 |
| 优化器状态 | 历史统计与更新 | 类型、位数、是否分页需另记录 |
| 未量化模块 | 例如按实现保留的归一化等 | 不保证整个模型的每个张量都是 4-bit |

- 原论文第 3 节用 NF4 表示基模权重，并以 BF16 表述计算和 LoRA 矩阵。
- 工程实现中的 adapter 存储可能是 FP32 或其他浮点类型；计算也可能经 autocast，不能仅凭一个 BF16 配置推断所有张量精度。
- 参数存储、算子输入、内部累加和优化器状态不是同一个配置。
- 正式训练应打印并记录实际 dtype，而不是统一写“用了半精度”。

### 2.2 同一条数据流怎样计算

沿用前篇 `1024→2048` 的线性层，`A：[8,1024]`、`B：[2048,8]`。

```text
原权重保存：量化编码 + 缩放等量化状态
                             |
                             v
输入 x ── 原分支：按需反量化得到近似权重 ── 矩阵运算 ── 原分支输出
   └──── LoRA 分支：浮点 A ── 浮点 B ── 缩放 ────────── 调整输出
两路相加：输出形状仍为 [N, T, 2048]
```

按单个 token 的列向量写法：

\[
\widetilde W=D(q,\theta),\qquad
y=\widetilde Wx+sBAx
\]

| 符号 | 含义 |
| --- | --- |
| q | 量化权重编码 |
| theta | 缩放等量化状态 |
| D | 反量化重建过程 |
| W 波浪号 | 以浮点表示的近似权重，逻辑形状仍为 `[m,n]` |
| s | 标准 LoRA 的 alpha/r 缩放 |

- 量化不改变模型参数数量和逻辑矩阵形状；打包存储的实际 tensor 布局可能改变。
- 具体内核可能按层或融合处理反量化，不能把流程图理解成把整个基模长期完整恢复为 BF16 后再训练。
- 反量化用于前向以及反向需要的相关运算；更新的仍是浮点 A/B，不是对离散编码执行普通梯度下降。

### 2.3 反量化不是恢复原始精确数值

自拟示意：若某种量化把两个原值映射到同一代表值，那么只有编码和缩放信息无法再区分它们。

```text
原值 0.123 → 选择代表值 0.12
原值 0.124 → 选择代表值 0.12
反量化只能得到对应近似值，不能知道原来是哪一个
```

这里的 0.12 只是教学示意，不是 NF4 码本值。转成更高精度类型只改变容纳近似值的格式，不补回已经丢失的信息。

## 3. NF4：怎样安排 16 个代表值

### 3.1 为什么不是简单均匀分配

- 4-bit 可表示 `2^4=16` 种编码，每个编码对应一个代表值。
- 若这些值在区间内均匀分配，某些密集数值区域得到的表示可能不够细。
- NF4 依据零中心正态分布的分位数构造非均匀码本，零附近更密，并保留精确的零表示。
- 其动机来自权重常呈现近似正态分布的观察；不是断言所有权重都严格正态，也不是所有数据类型的通用最优量化器。

本文不推导完整分位数公式和列出 16 个码本数值，保留需要理解的机制；完整构造见论文第 3 节与附录 E。

### 3.2 分块、归一化、编码

设一块权重为 `w_i`，本节定义缩放值 `c=max(abs(w_i))`。归一化后的权重约落在 `[-1,1]`：

\[
\bar w_i=w_i/c,\qquad
q_i=\operatorname{encode}_{NF4}(\bar w_i),\qquad
\widetilde w_i=c\cdot\operatorname{codebook}_{NF4}[q_i]
\]

以上说明非全零块；全零块需由实现专门处理，不能直接除以零。这里将 c 定义为 absmax，有些代码采用其倒数或其他缩放记法，阅读时应先核对定义。

| 步骤 | 做什么 | 需要保存什么 |
| --- | --- | --- |
| 分块 | 把权重切成较小块分别处理 | 布局等量化状态 |
| 求缩放 | 让块内值落入合适范围 | 每块缩放值 |
| 选择代表值 | 将归一化值映射到码本 | 每个权重的 4-bit 编码 |
| 反量化 | 查码本，再结合缩放重建 | 使用前面的编码与状态 |

### 3.3 分块有什么意义

- 不同块可使用不同缩放值，避免一个特别大的权重决定整个大张量的表示间距。
- 相同编码在不同块可以表示不同大小的值，因此不是“整个模型只有 16 种权重”。
- 块越小，局部表示可能更精细，但需要保存更多缩放信息；这引出双重量化。
- 分块减少问题，不保证消除所有异常值影响或量化误差。

## 4. 双重量化：压缩辅助信息

### 4.1 第二次量化的对象是谁

第一层量化后，还要保存每块的缩放值。Double Quantization 将这些缩放值也进行量化，进一步节省内存。

```text
第一次：原权重 → 4-bit 编码 + 每块缩放值
第二次：每块缩放值 → 较低位表示 + 更高一层的缩放等状态

重建时：先重建缩放值，再用它重建权重近似值
```

- 第二次压缩的是第一层的量化常数，不是直接把同一批 NF4 权重再变粗一次。
- 第二层仍需少量状态，因此不是把缩放信息完全删除。
- 缩放常数的量化也可能带来误差；是否影响任务表现需要实测。

### 4.2 原论文的开销例子

论文第 3 节采用第一层块大小 64；每块若存一个 FP32 缩放值：

\[
32/64=0.5\ \text{bits/weight}
\]

第二层将缩放值以 8-bit 表示，每 256 个缩放值再配一个 FP32 常数，论文按主要项目估算：

\[
8/64+32/(64\times256)\approx0.127\ \text{bits/weight}
\]

| 主要开销 | 单重量化 | 双重量化 |
| --- | --- | --- |
| 权重编码 | 4 bits/weight | 4 bits/weight |
| 缩放信息的平均开销 | 约 0.5 bits/weight | 约 0.127 bits/weight |
| 合计主要存储项 | 约 4.5 bits/weight | 约 4.127 bits/weight |

- 这解释论文报告的约 0.373 bits/weight 节省来自哪里。
- 是特定块配置下的主要项目估算，不是任意模型文件大小或训练峰值显存的精确公式。
- 还可能有布局、其他元数据、未量化模块等，不能用参数量乘 0.5 字节代表整个训练占用。

## 5. 分页优化器：应对显存峰值

### 5.1 优化器状态与参数不是同一对象

- Adam/AdamW 保存梯度的一阶、二阶历史统计量，用于计算更新。
- 纯 LoRA 设置下这些状态主要对应可训练 adapter，而不是给全部冻结基模保存 Adam 状态。
- 激活、反向中间量和临时算子空间也会变化；因此平均能装下，不代表峰值一定能装下。

### 5.2 分页怎样工作

原论文的 paged optimizer 利用 NVIDIA CUDA unified memory，将优化器状态分配到支持按页迁移的内存中。

```text
有需要时：状态页由 GPU 迁出到 CPU 内存
更新需要访问时：相应页再迁回 GPU
目标：缓解短时显存压力，而不是改变学习目标
```

| 概念 | 主要作用对象 | 是否等同分页优化器 |
| --- | --- | --- |
| NF4 | 基模权重编码 | 否 |
| 双重量化 | 量化缩放信息 | 否 |
| 8-bit optimizer | 优化器状态的表示位数 | 否，状态位数与是否分页是不同选择 |
| paged optimizer | 优化器状态的内存放置与迁移 | 是 |
| activation checkpointing | 部分前向中间结果，通过重计算换空间 | 否，可与分页等配合 |

### 5.3 能解决和不能解决的事

- 分页缓解的是它所管理状态的内存压力，不会让所有激活或临时空间自动可分页。
- 页迁移需要 CPU 内存及传输，频繁迁移可能增加每步耗时。
- 不是任意 batch、序列长度和模型都能不 OOM；仍需观察完整运行峰值。
- 原论文的 CUDA 机制不能直接证明海光 DTK 上可用；算子和内存管理必须分别验证。

## 6. 量化后，反向怎样继续

沿第 2 节的列向量公式，并沿用前篇定义的 `g=∂L/∂y`，对 A/B 的推导仍是：

\[
\frac{\partial L}{\partial B}=sg(Ax)^T,\qquad
\frac{\partial L}{\partial A}=s(B^Tg)x^T
\]

若上游需要输入梯度：

\[
\frac{\partial L}{\partial x}=\widetilde W^Tg+sA^TB^Tg
\]

- 这些是对当前近似计算的导数，不是对未量化原模型的精确梯度。
- 上游学习信号仍会经过冻结基模分支；冻结不等于把这部分包进 `no_grad()`。
- q 和量化常数在本篇的标准冻结设置中不由 optimizer 更新。
- 不需要对离散量化编码进行普通可微更新；A/B 使用浮点参与前向、反向与 step。

## 7. 工程配置如何对应原理

下段是官方 API 风格的配置示意，不是已经验证的安装、分布式或海光运行配方。使用前需固定版本和受支持的环境。

```python
import torch
from peft import LoraConfig
from transformers import BitsAndBytesConfig

quantization = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=torch.bfloat16,
)

adaptation = LoraConfig(
    task_type="CAUSAL_LM",
    r=8,
    lora_alpha=16,
    lora_dropout=0.0,
    target_modules=["q_proj", "v_proj"],
    bias="none",
)
```

| 配置 | 决定什么 | 不决定什么 |
| --- | --- | --- |
| load_in_4bit | 加载时采用 4-bit 量化的相关模块 | 全部张量都为 4-bit |
| quant_type=nf4 | 量化代表值方案 | adapter 的存储类型 |
| use_double_quant | 是否压缩缩放信息 | 是否分页 optimizer |
| compute_dtype=BF16 | 量化线性计算使用的浮点类型 | 全模型参数、状态和累加都为 BF16 |
| r、alpha、target_modules | LoRA 参数化与挂载 | NF4 的码本或 block size |
| optimizer 的分页配置 | 状态迁移方式 | 不由上面的两个配置对象自动选定 |

- 实际加载量化基模后，还需按框架准备训练、注入 adapter、检查可训练参数并创建 optimizer。
- 示例中的 `r=8`、Q/V 挂载不是推荐最佳值；仍以真实模型名称、研究条件和评测为准。
- 本轮完成语法检查，未加载真实基模或运行量化训练，不报告任何硬件适配成功。
- 不把推理用 `device_map="auto"` 示例直接当作多卡训练策略；训练并行方式另行配置与验收。

## 8. 成本与方法选择

### 8.1 为什么训练显存不一定降到四分之一

粗略拆分完整峰值：

```text
冻结基模存储及量化状态
+ 可训练参数、梯度、优化器状态
+ 激活及为反向保存的中间量
+ 反量化、算子、通信等临时空间
+ 内存分配与缓存开销
```

- 16-bit 权重改用 4-bit 编码，减少的是主要权重编码项，而不是每一项。
- 双重量化减少额外状态，分页调整部分状态的放置，checkpointing 处理部分激活，作用层次不同。
- 训练耗时还受反量化内核、计算能力、传输和并行方式影响；省显存不等于一定更快。

### 8.2 对我们测试模型的选择建议

以下是团队工程建议，不是作者提供的测试领域最佳配方。

| 条件 | 候选选择 | 仍需确认 |
| --- | --- | --- |
| 浮点 LoRA 能满足显存与吞吐要求 | 可先建立浮点 LoRA 对照 | 目标效果与基础能力回归 |
| 冻结基模权重占用成为主要限制 | 评估 QLoRA | 量化前后基线差异、训练稳定性与算子支持 |
| 长日志或 batch 导致激活峰值大 | 同时检查序列、batch、checkpointing 等 | 不能只换 QLoRA 就认为问题解决 |
| 非 CUDA 平台，量化与分页支持未确认 | 先做独立功能与数值探针 | 不能从总显存或库能安装推导可训练 |

用户提供的计划设备是海光 BW1000、8 卡、单卡 64 GB；这是设备计划，不是本轮实测。

- 没有实测 DTK、PyTorch、量化内核、分页 optimizer 和多卡组合，不能宣称原论文方案在该平台可用或不可用。
- 若后续比较 LoRA 与 QLoRA，应固定基模身份、数据切分、监督、评测及明确的训练预算口径。
- 还要分别测浮点原基模与量化未微调基模，避免把量化本身的变化全归因于 adapter 训练。

## 9. 保存与部署的边界

- adapter 仍不是完整模型，需要指定基模、量化方案、tokenizer、模板和运行依赖。
- “量化基模加 adapter”与“浮点基模加相同 adapter”不是同一个计算条件，部署更换条件要重新评测。
- 合并前需重建可运算权重或使用受支持的合并实现，不能直接给 4-bit 编码加浮点 `BA`。
- 合并后再量化可能引入新的舍入误差；关闭 dropout 等条件后，也应比较实际输出。
- 推理 adapter 与完整恢复 checkpoint 分开管理，不能用前者替代优化器等恢复状态。

## 10. 我们保留的结论与疑问

| 问题 | 当前可以确定的机制 | 不应扩大成的结论 |
| --- | --- | --- |
| A/B 用什么精度？ | 浮点训练，不是冻结基模的 NF4 更新 | 所有库都存为 BF16 |
| 反量化恢复原值吗？ | 重建近似值 | 无损恢复原模型 |
| NF4 为何非均匀？ | 针对分布安排有限代表值 | 对所有权重和任务普遍最优 |
| 双重量化是什么？ | 压缩第一层的量化常数 | 同一批 NF4 编码再粗糙化一次 |
| 分页 optimizer 有什么用？ | 迁移所管理状态，缓解峰值 | 任意训练都不会 OOM |
| QLoRA 是否更好？ | 提供更省存储的训练候选 | 一定更快或比浮点 LoRA 更准 |

原论文在所测模型与任务上报告了接近或匹配 16-bit 微调的表现。对我们来说，这支持把 QLoRA 列为候选方案，不提供现成的最佳数据量、rank、架构或业务可用标准。
