# 从梯度到参数更新：SGD 与 AdamW

> 更新：2026-10-13。先理解每一步的作用，再沿一个数值例子串起计算；本文不要求一次记住全部公式。

[优化目录](README.md) · 前置：[自动求导与参数更新](../01_model_architecture/foundations/08_AUTOGRAD_AND_PARAMETER_UPDATES.md) · 实践：[MiniMind 第五周](../../training_engineering/case_studies/minimind/practice_notes/week_05_training_system.md)

## 1. 参数更新在训练中的位置

模型前向计算产生预测，loss 表达当前目标，反向传播说明参数怎样影响 loss。优化器接在反向传播之后，决定本次怎样改变参数。理解优化器，先要看清这两段计算之间传递的是什么。

```python
loss.backward()   # 计算并累积参数梯度
optimizer.step()  # 读取梯度，按优化规则更新参数
```

它们之间传递的是参数的 `.grad`。对于一个标量参数，它是一个数；对于矩阵参数，它是同形状矩阵，其中每项是 loss 对相应参数元素的偏导。backward 通常由自动求导沿计算图执行，optimizer 不需要重算模型前向或重新定义 loss。

最简单的观察目标是 `L(w)=w²`。参数 w=2 时，loss=4，梯度 g=2w=4。这里 loss 与梯度数值碰巧相同，但作用不同：前者描述当前目标值，后者描述当前位置附近的变化率。

整个训练关系为：

```text
参数、输入 -> 前向 -> loss -> backward -> 参数梯度
                                                |
                            优化器规则与状态 -> 参数更新
                                                |
                                      下一次前向使用新参数
```

同样的起点和目标会给出同样的梯度，但更新规则可以不同。下面始终围绕这个标量目标展开；进入真实模型时，对各个参数元素应用相应计算。

## 2. SGD：由当前梯度直接确定变化量

### 2.1 学习率与局部方向

普通 SGD 在这里指无动量、无权重衰减的形式：

\[
w_t=w_{t-1}-\eta g_t
\]

w 是参数，g 是当前梯度，η 是学习率，t 是更新次数。梯度给出局部变化方向与尺度，学习率决定沿它走多大一步。

在 w=2、g=4、η=0.1 的例子中：

```text
变化量 = 0.1 × 4 = 0.4
新参数 = 2 - 0.4 = 1.6
```

若打印 `after-before`，结果是 -0.4；如果把 update 定义为公式中被减去的量，则 update=+0.4。两种记法均可，但应保持符号一致。

这里的正梯度意味着微增 w 会增加 loss，减小 w 可降低当前平方目标。不过局部导数不保证任意步长都能改善目标，学习率过大可能越过合适区域甚至使 loss 增长。

### 2.2 为什么仅有当前梯度还不够

真实训练通常在不同 batch 上求梯度。数据不同、模型位置变化，都会让梯度方向与大小改变。只根据这一次观测更新，有时会沿某些方向反复摆动，也可能在不同参数维度上遇到不同的梯度尺度。

历史平均与按尺度调整，是处理这些情况的两种思路。下面的 AdamW 同时包含它们；这些机制提供可用的更新策略，并不保证在所有目标上优于 SGD。

## 3. 历史统计：m 与 v 的递推

### 3.1 m：结合近期梯度

Adam 系列保存梯度的指数移动平均，记为 m：

\[
m_t=\beta_1m_{t-1}+(1-\beta_1)g_t
\]

取 β1=0.9，可读成“保留旧统计的 90%，加入当前梯度的 10%”。连续递推后，越早的梯度被反复乘以 0.9，权重逐渐减小。这里的百分比对应两项的加权关系，不能理解为只更新 10% 的模型参数。

第一次更新 m0=0、g1=4，所以 m1=0.4。若为了理解而假设第二次梯度为 -2，m2=0.9×0.4+0.1×(-2)=0.16。当前梯度已改变符号，历史平均仍为正。这是“惯性”类比的具体含义：过去的梯度继续影响当前的更新方向。

这个 -2 是假设，不能当作当前平方目标的实际下一步。参数更新到约 1.9 后，再对 `w²` 求导，真实梯度约为 3.8。

### 3.2 v：结合近期梯度平方

第二份状态记为 v：

\[
v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2
\]

默认 β2=0.999，即保留旧统计的 99.9%，加入当前梯度平方的 0.1%。平方使正负号消失，v 记录近期梯度大小的信息。它是原点二阶矩的移动平均，不能直接称为中心化后的统计方差。

初始 v0=0、梯度 g1=4 时：

```text
m1 = 0.9 × 0 + 0.1 × 4 = 0.4
v1 = 0.999 × 0 + 0.001 × 4² = 0.016
```

m 与梯度的量纲一致，v 对应梯度平方；取 sqrt(v) 后再与 m 比较，能形成后续调整尺度的比值。在矩阵参数中，这些乘法、平方和除法都是逐元素计算，每个元素有自己的历史统计。

## 4. 偏差修正：处理初始零状态的影响

### 4.1 初始零为何让统计向零收缩

第一次只观测到梯度 4，但 m1=0.4。原因是 90% 的权重仍落在初始零上，实际梯度只得到 10%。偏差修正针对这个初始化影响，原来的递推公式仍然保留。

展开前两次 m 的递推：

\[
m_1=(1-\beta_1)g_1
\]

\[
m_2=\beta_1(1-\beta_1)g_1+(1-\beta_1)g_2
\]

β1=0.9 时，第二行是 `m2=0.09*g1+0.1*g2`。真实梯度的权重总和只有 0.19；另外 0.81 对应已经衰减两次的初始零。

推广到 t 次，真实观测的权重总和为：

\[
(1-\beta)\sum_{k=0}^{t-1}\beta^k=1-\beta^t
\]

除以这个权重总和，就把真实观测重新归一为总权重 1 的历史加权平均。以梯度具有相同均值的理想情形解释，它消除了零初始化对均值估计的偏差；真实训练中梯度分布不断改变，不能据此声称得到了当前的精确梯度或消除了噪声。

### 4.2 修正值与保存状态

修正后的统计写为：

\[
\hat m_t=\frac{m_t}{1-\beta_1^t},\qquad
\hat v_t=\frac{v_t}{1-\beta_2^t}
\]

帽子表示修正后的量。t 是该参数参与的更新次数，不能直接用 epoch 或任意 micro-batch 计数代替。下一次递推仍使用保存的 m/v；hat 值参与当前更新计算，不替换原始状态。

对于实际第一步 t=1：

```text
m_hat = 0.4 / (1-0.9) = 4
v_hat = 0.016 / (1-0.999) = 16
```

第一次的修正值等于唯一观测的梯度及其平方。多次更新后，它们是历史加权统计，通常不等于当前 g 和 g²。

## 5. 更新尺度：从修正值计算参数变化

先令 weight_decay=0，使用默认的最小化目标、非 AMSGrad 形式：

\[
\Delta w_t=\eta\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon},\qquad
w_t=w_{t-1}-\Delta w_t
\]

分子保留综合后的梯度方向，分母依据近期梯度大小调整尺度，学习率控制整体步长。eps 是分母中的小正数，避免除零并改善数值稳定性，位置在平方根之外。这套计算与默认参数可对照 [PyTorch 2.14 AdamW 文档](https://docs.pytorch.org/docs/2.14/generated/torch.optim.AdamW.html)。

### 5.1 第一次更新的完整数值

继续使用 η=0.1、eps=1e-8：

```text
梯度 g=4
  -> m=0.4，v=0.016
  -> m_hat=4，v_hat=16
  -> update=0.1×4/(sqrt(16)+1e-8)≈0.1
  -> w_new=2-update≈1.9
```

把它与 SGD 对照：两者的梯度都是 4，但 SGD 使用 `η*g`，这里的 AdamW 使用 `η*m_hat/(sqrt(v_hat)+eps)`，所以得到不同参数变化。

### 5.2 为什么第一步接近学习率大小

对于非零标量梯度、首次更新、零初始状态、无权重衰减，且 eps 远小于梯度绝对值的情况，有 `m_hat=g`、`sqrt(v_hat)=|g|`，所以 update 约为 `η*sign(g)`。

这解释了当前现象，但不能推广为所有更新固定变化一个学习率。后续的 m/v 含有历史信息，eps、weight decay 和不同参数的梯度都会影响结果。平滑也不等于稳定保证；学习率过大仍可能使训练失稳。

## 6. AdamW 的权重衰减

当前数值例子关闭了 weight decay，展示的是 AdamW 的自适应梯度更新部分。AdamW 与经典 Adam 的主要区别在于如何加入权重衰减，这也是算法名称中的 W 所对应的内容。

令衰减系数为 λ，常用形式为：

\[
w_t=(1-\eta\lambda)w_{t-1}
-\eta\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}
\]

其中第一项按当前参数大小施加衰减，第二项来自梯度统计。衰减项没有加入 g 的历史统计，因此称为解耦。

如果把 L2 项加到 loss，例如 `L_total=L+(λ/2)||w||²`，反向得到的梯度会增加 λw。将这个梯度交给自适应优化器，会让新增项进入 m/v 并被自适应缩放，与上面的直接衰减一般不等价。[Decoupled Weight Decay Regularization](https://arxiv.org/abs/1711.05101)讨论了这一差异。

衰减可作为约束参数规模的一种方法，不能保证泛化改善。实际模型中哪些参数应用衰减、系数取多少，要结合参数组与实验确定；本次只建立更新公式的完整背景，不将尚未完成的参数组实践标成验收。

## 7. 代码对象与状态读取

### 7.1 参数集合与参数组

优化器接收可遍历的参数集合：

```python
optimizer = torch.optim.AdamW([parameter], lr=0.1, weight_decay=0.0)
```

单个 Parameter 外面的方括号是列表，不复制参数。完整模型通常传入 `model.parameters()`。如果建立多个参数组，每组可以指定自己的 lr、weight_decay 等配置；当前只有一组，所以读取 `optimizer.param_groups[0]`。

`param_groups` 保存哪些参数使用什么配置；`state` 保存各个参数已经积累了什么历史。这两者是不同对象。

### 7.2 参数对象作键

当前参数完成第一次更新后，可读取：

```python
state = optimizer.state[parameter]
step = state["step"].item()
m = state["exp_avg"].item()
v = state["exp_avg_sq"].item()
```

第一层按参数对象取出状态字典，第二层按字符串键读取其中一项。它不是按当前参数数值查找；另建一个数值相同的 Parameter 仍是另一个对象。局部变量 state 引用这份字典，读取不会自行更新参数。

本机实现使用 `defaultdict(dict)`，访问没有登记的参数键会创建空字典，因此观察前需确认该参数已经有梯度并执行了更新。与此不同，序列化的 `optimizer.state_dict()` 通常用参数 ID 编码映射，不应把这里的直接对象索引原样套到序列化结果中。

这里 `.item()` 适用于单元素状态。真实矩阵参数的 m/v 与参数同形状，要打印矩阵或选择有意义的统计，不能直接对整个多元素矩阵调用 `.item()`。

### 7.3 手算对照需要固定什么

对照起点、loss、梯度、更新次数、beta、学习率、eps、weight decay 和计算精度。SGD 与 AdamW 的两个分支应有独立参数对象，以免前一分支的更新污染后一分支的起点。

更新前标量可用 `.item()` 保存 Python 数值；矩阵快照通常用 `detach().clone()`。计算 predicted_after 时，要使用更新前的快照，不能从已经被 step 改过的参数再减一次更新量。

## 8. 验证与常见遗漏

手算并不只是重复一个公式，而是在检查从梯度统计到参数变化的连接。可以分别对照 m/v、hat 值、update 和最终参数，这样遇到差异时能知道从哪一段开始排查。

一个实际出现的遗漏是：

```python
update = m_hat / (v_hat ** 0.5 + eps)
```

它只计算了按尺度调整后的量，尚未乘学习率。当前例子得到约 1，于是预测参数约为 `2-1=1`，与实际约 1.9 不同。完整变化量还需要 lr：

```python
update = lr * m_hat / (v_hat ** 0.5 + eps)
```

程序能正常退出只说明没有运行异常，不能说明数学对照成立。完成修正后，应以合理的浮点容差比较 predicted_after 与实际参数；当前状态来自 float32，手算经 `.item()` 转成 Python 数值，因此不要求二进制数逐位相同。

其他容易混淆的边界包括：把 loss 数值当作梯度；把 m 当作参数变化量；把 v 当成方差；用 hat 状态继续递推；给默认 SGD 添加动量后仍按普通 SGD 公式解释；只保存模型参数却误以为恢复了优化器历史。

当前一维单步对照检查的是一个有限配置。它不证明多步、矩阵参数、权重衰减或完整训练都正确，后续验证应随实际实现逐步增加。

## 9. 与整体训练的连接

回到语言模型，loss 对 logits 的导数沿 LM head、Decoder 和 Embedding 的计算图传播，形成各组参数的梯度。AdamW 在参数空间中利用这些梯度和各自历史进行更新；下一次前向才会看到新的 logits 和 loss。

优化器不直接指定某个隐藏特征应该表达什么，也不能独自解决错误数据、目标偏差或评测污染。它控制的是当前学习信号怎样变成参数变化。学习率调度改变步长计划，梯度累积组织一次更新的监督量，裁剪调整过大梯度；这些机制将沿同一条训练链进一步展开。

读完本文，应能沿一个问题复述机制：对于已知的梯度，当前优化器为什么产生这一次参数变化？需要进一步理解求导路径时回到自动求导篇，需要核对真实代码与运行结果时回到第五周实践。
