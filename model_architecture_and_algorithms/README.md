# 模型架构与算法

这里整理可跨项目复用的原理：模型怎样处理信息，学习信号怎样改变参数，以及不同方法为什么适合不同问题。
它不是另一份周计划。实践进度仍以各案例的路线与记录为准。

## 阅读入口

从[模型基础：从预测任务到可训练网络](01_model_architecture/foundations/README.md)开始。
这组文章以语言模型为贯穿案例，把数学、组件和反向传播连成一条链路。

## 分类原则

按“正在解释什么”归类，而不是按“在哪一次聊天中提到”归类：

| 类别 | 核心问题 | 内容示例 |
| --- | --- | --- |
| 模型架构 | 信息如何表示和流动？ | Embedding、Attention、FFN、残差、具体模型结构 |
| 训练目标 | 什么行为受到奖励或惩罚？ | NLL、SFT masking、DPO 目标、策略梯度目标 |
| 优化 | 如何根据梯度改变参数？ | SGD、AdamW、学习率、裁剪 |
| 参数适配 | 更新哪些参数，怎样表示更新量？ | 全参、冻结、LoRA、QLoRA |
| 训练阶段 | 为了目标能力，怎样组织数据和方法？ | 预训练、SFT、偏好优化、Agent 训练 |
| 推理 | 参数固定后怎样产生和控制输出？ | 解码、KV cache、停止条件 |

当前已落地的是模型架构下的基础系列；其他类别在形成文章时再扩展。
基础系列涉及 loss 和梯度，是为了闭合网络计算；完整的优化算法与阶段比较仍应放在对应类别。
例如，“SFT 为什么使用示范数据”属于阶段设计，“哪些 token 进入交叉熵”属于目标定义，两者互相链接。

## 文档边界

通用原理放在这里，具体模型结构分析归入模型架构下的案例子目录；
配置、数据版本、运行记录和故障复盘留在[训练工程案例](../training_engineering/case_studies/)。
前沿观察记录新材料和待验证判断，不能直接代替原理依据或实验证据。

公式需要说明符号与对象，类比不能替代机制，测试需要说明它排除了什么错误。
目标是讲清现有计算为什么这样组织，而不只是堆积名称、API 和速查表。
